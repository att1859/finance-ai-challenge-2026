# ADR 0001: 단일 사이트의 데모 셸과 역할별 제품 표면

## Status

Accepted

## Context

데모는 운영자 도구와 고객 앱의 연속 흐름을 한 자리에서 보여줘야 한다. 기존 구현은 역할 전환과 초기화가 제품 화면 안에 섞여 실제 사용자의 정보구조를 흐렸다. 운영자와 고객을 별도 프로젝트로 분리하면 역할은 선명해지지만 대회 시연의 연속성과 배포 단순성이 낮아진다.

## Decision

하나의 React 애플리케이션을 유지하되 최상위에 데모 컨트롤을 둔다. 데모 컨트롤은 역할·시나리오·초기화를 소유하고, 운영자 도구와 고객 앱은 각자의 제품 내비게이션과 언어만 가진다. 고객 앱은 게시된 고객 케이스 ID로만 진입한다.

## Consequences

- 한 URL에서 전체 시연이 가능하다.
- 발표 기능과 실제 제품 기능의 시각적·의미적 경계가 명확해진다.
- 운영자와 고객 화면은 같은 도메인 상태를 공유하지만 서로 다른 컴포넌트 트리를 사용한다.
- 실제 배포로 확장할 때 데모 컨트롤을 제거하고 두 표면을 별도 진입점으로 나눌 수 있다.
- 고객 케이스 ID와 상태 소유권을 엄격하게 관리해야 한다.
