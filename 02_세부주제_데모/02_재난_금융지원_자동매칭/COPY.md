# 역할별 문구 원칙

## 공통 원칙

- 가능성을 자격 확정처럼 말하지 않는다.
- AI보다 사용자의 현재 사실과 다음 행동을 먼저 말한다.
- 고객 행동과 은행 내부 처리를 한 버튼에 합치지 않는다.
- `안전`, `보안`, `공식 확인`은 근거가 화면에 있을 때만 쓴다.

## 운영자 문구

- `받을 수 있는 대표 지원 3개` → `검토 가능한 지원 3개`
- `고객 앱에 안전하게 노출` → `선택 고객에게 앱 안내 게시`
- `분석 승인·케이스 생성` → `분석 승인하고 고객 찾기`
- `자동 선별 근거` → `우선 확인 근거`
- 게시 확인 제목: `{고객명} 고객에게 안내를 게시할까요?`
- 게시 설명: `사업장과 추천 지원을 다시 확인하세요. 고객이 제출하기 전에는 게시를 취소할 수 있습니다.`

## 고객 문구

- 제목: `{고객명}님이 확인할 수 있는 재난지원 안내가 있어요.`
- 설명: `은행이 보유한 사업장·대출 정보와 재난지원 공지를 대조했습니다. 실제 지원 여부는 피해 확인과 기관 심사를 거쳐 결정됩니다.`
- `우선 확인할 지원 3개` → `검토 가능한 지원 3개`
- `AI로 피해 내용 분류` → `피해 내용 정리하기`
- AI 설명: `말씀해주신 내용을 신청에 필요한 항목으로 정리합니다. AI가 지원 자격을 결정하지 않습니다.`
- `신청 제출·심사 이관` → `신청서 제출`
- `정책기관 연계` → `소진공 확인 후 은행 접수`
- `외부 승인 필요` → `보증기관 심사 필요`
- 제출 완료: `신청서를 은행에 보냈어요.`
- 은행 접수: `은행 담당자가 신청서를 확인하고 있어요.`
- 심사 이관: `담당 심사부서로 전달했어요.`

## 데모 문구

- `합성 데이터 데모`
- `화면과 상태는 시연을 위한 합성 정보입니다.`
- 역할: `운영자 도구`, `고객 앱`
- 고객 앱 미게시 상태: `현재 선택 고객에게 안내를 먼저 게시하세요.`

## 금지 표현

- 받을 수 있습니다
- 지원 대상자로 선정됐습니다
- 자동 승인
- 자동 지급
- 피해 세그먼트
- 안전하게 노출
- 신청 제출·심사 이관
- 고객 화면 안의 담당자 화면 전환
