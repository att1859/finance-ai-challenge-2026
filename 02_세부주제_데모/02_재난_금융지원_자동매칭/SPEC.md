# V2 기능 명세

## 1. 목적

재난금융 자동매칭의 핵심 가치인 “은행이 먼저 대상 가능성을 찾고, 고객은 빠짐없이 이해한 뒤 신청한다”를 하나의 시연 가능한 웹사이트에서 증명한다.

## 2. 제품 표면

### 2.1 데모 컨트롤

- 모든 화면 최상단에 얇은 별도 영역으로 표시한다.
- 운영자 화면과 고객 앱을 전환한다.
- 침수·산불·폭설 시나리오를 전환한다.
- 현재 화면이 합성 데이터 데모임을 지속적으로 표시한다.
- 전체 상태를 초기화한다.
- 고객 앱은 현재 선택 케이스가 게시된 경우에만 연다.
- 비활성 이유를 텍스트로 설명한다.

### 2.2 은행 운영자 도구

- 재난의 지역, 사건일, 신고기한, 공식 출처를 표시한다.
- 지원공지 원문을 AI 구조화하고 저장 분석 사용 여부를 알린다.
- 담당자가 구조화 결과를 승인해야 고객 우선순위를 생성한다.
- 전체 합성 고객 100명을 검색·필터·정렬하고 점수 근거를 확인한다.
- 선택 고객의 대출, 납부일, 추천 3개, 추가 추천을 확인한다.
- 게시 전 고객명·사업장·추천 3개를 재확인한다.
- 고객 제출 후 은행 접수와 심사 이관을 각각 수행한다.
- 고객이 제출하기 전에는 게시를 취소할 수 있다.

### 2.3 고객 앱

- 담당자 화면으로 이동하는 제품 내 버튼을 두지 않는다.
- 고객명, 안내 이유, 신고기한을 표시한다.
- “검토 가능한 지원 3개 → 신청 기한 → 필요서류” 순서를 유지한다.
- 피해 진술을 텍스트로 입력·수정하고 AI 구조화 결과를 확인한다.
- AI가 자격을 결정하지 않는다는 사실을 보조 설명으로 제공한다.
- 필요서류 준비 여부를 확인하고 신청서를 제출한다.
- 제출 후 은행 접수 전까지 신청을 취소할 수 있다.
- 제출·접수·이관 상태, 예상 처리시간, 문의처를 고객 언어로 표시한다.

## 3. 핵심 상태

### 3.1 공지

`idle → analyzing → analyzed → approved`

- API 실패 시 `analyzed` 상태는 유지하되 분석 출처를 `cache`로 표시한다.
- 승인 전에는 고객 추천과 앱 게시를 열지 않는다.

### 3.2 지원 케이스

`candidate → ready → published → customer_confirmed → application_submitted → bank_received → transferred`

- `ready`: 공지 승인 후 고객별 추천이 생성된 상태
- `published`: 앱 안내가 게시된 상태
- `customer_confirmed`: 고객이 피해내용 구조화를 확인한 상태
- `application_submitted`: 고객 신청서 제출 상태
- `bank_received`: 은행 담당자 접수 상태
- `transferred`: 심사부서 이관 상태

취소 전이는 `published → ready`, `application_submitted → published`만 허용한다.

## 4. 매칭과 우선순위

- 영향지역 일치: 50점
- 피해 가능성 신호: 20점
- 납부일까지 14일 이내: 20점
- 지원 검토 가능한 보유대출: 10점
- 동점은 납부일까지 남은 날이 적은 순, 그다음 고객 ID 순으로 정렬한다.
- 점수는 자격이나 피해 심각도를 의미하지 않는다.
- 운영자 화면에서 항목별 점수와 근거를 확인할 수 있어야 한다.

## 5. 검색·필터·정렬

- 검색: 고객명, 사업장명, 지역
- 지역 필터: 전체, 영향지역
- 납부 필터: 전체, 14일 이내
- 상태 필터: 전체, 안내 전, 게시, 고객 제출, 은행 접수, 이관
- 정렬: 우선도, 납부일, 고객명
- 초기 20명을 보여주고 더 보기를 통해 전체 결과에 접근한다.
- 결과 없음 상태에는 필터 초기화 행동을 제공한다.

## 6. 날짜

- 세 시나리오는 실행일 기준 신청 가능한 데모 날짜를 생성한다.
- 사건일, 신고기한, 다음 납부일은 정적 문자열이 아니라 날짜 계산 결과다.
- D-day는 당일 `D-Day`, 미래 `D-n`, 종료 `기한 종료`로 계산한다.
- 이번 V2에서는 종료 상태가 정상 흐름에서 발생하지 않도록 시나리오 기한을 미래로 둔다.

## 7. 오류·복구

- 빈 피해 진술은 분석하지 않고 입력란 가까이에 이유를 알린다.
- AI 호출 실패 시 저장 분석 사용 사실과 다시 시도 가능성을 알린다.
- 중복 클릭 중에는 버튼을 비활성화한다.
- 잘못된 고객 게시를 막기 위해 게시 확인 단계를 둔다.
- 제출·접수·이관은 각 단계 성공 피드백을 표시한다.
- 새로고침 후에도 현재 시나리오와 고객별 상태를 복원한다.

## 8. 접근성

- 고객 행 선택은 실제 버튼 의미와 `aria-pressed`를 유지한다.
- 펼침 버튼은 `aria-expanded`를 제공한다.
- 비동기 분석과 상태 전환은 `aria-live` 영역에서 알린다.
- 모든 주요 행동은 키보드로 수행할 수 있다.
- 고객 입력은 16px 이상으로 모바일 자동 확대를 방지한다.

## 9. 비기능 요구사항

- React, Vite, Seed Design System을 유지한다.
- PC 운영자 화면을 우선하되 390px 고객 화면이 깨지지 않아야 한다.
- 합성 데이터 외 개인·금융정보를 사용하지 않는다.
- 자동 승인, 자동 지급, 자격 확정 표현을 금지한다.
