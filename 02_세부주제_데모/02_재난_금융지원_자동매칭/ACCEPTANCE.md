# V2 완료 조건

## 데이터 정확성

- [x] 운영자가 고객 B를 선택해 게시하면 고객 앱에 고객 B의 이름·사업장·피해 진술이 표시된다.
- [x] 고객 A의 서류·분석·신청 상태가 고객 B에게 복사되지 않는다.
- [x] 세 시나리오의 사건일·기한·납부일이 실행일 기준으로 계산된다.
- [x] D-day가 날짜 계산과 일치한다.

## 역할 분리

- [x] 역할 전환·시나리오 전환·초기화는 데모 컨트롤에만 있다.
- [x] 고객 앱 내부에 `담당자 화면` 문구가 없다.
- [x] 운영자 도구에서 시연용 `고객 앱 보기`가 제품 행동처럼 보이지 않는다.
- [x] 고객 앱은 게시된 케이스가 없으면 열리지 않는다.

## 고객 흐름

- [x] 고객이 피해 진술을 입력·수정할 수 있다.
- [x] 빈 진술은 분석할 수 없고 구체적인 오류가 표시된다.
- [x] 분석 후 고객이 피해 유형·지역·업종·피해자산을 확인한다.
- [x] 피해확인서 준비와 분석 확인 전에는 제출할 수 없다.
- [x] 제출 CTA는 `신청서 제출`이다.
- [x] 제출 후 고객은 은행 접수 전까지 신청을 취소할 수 있다.
- [x] 고객은 예상 처리시간과 문의처를 볼 수 있다.

## 운영자 흐름

- [x] 100명을 검색·필터·정렬할 수 있다.
- [x] 초기 20명 이후 더 보기를 통해 전체 결과에 접근한다.
- [x] 각 고객의 점수 항목별 근거를 확인할 수 있다.
- [x] 게시 전에 고객명·사업장·지원 3개를 재확인한다.
- [x] 고객 제출 후 은행 접수와 심사 이관이 별도 행동이다.
- [x] 고객 제출 전에는 게시를 취소할 수 있다.

## 안전·신뢰

- [x] 저장 분석을 사용하면 그 사실을 담당자와 고객에게 이해 가능한 문구로 알린다.
- [x] 지원 가능성을 확정 자격처럼 표현하지 않는다.
- [x] 자동 승인·자동 지급 문구가 없다.
- [x] 모든 고객 데이터가 합성임을 데모 컨트롤에서 지속 표시한다.

## 접근성·반응형

- [x] 고객 선택 버튼에 `aria-pressed`가 있다.
- [x] 더보기 버튼에 `aria-expanded`가 있다.
- [x] 상태 변경이 `aria-live`로 전달된다.
- [x] 1440px 운영자 화면과 390px 고객 화면에서 문서 가로 스크롤이 없다.
- [x] 키보드만으로 핵심 흐름을 완료할 수 있다.
