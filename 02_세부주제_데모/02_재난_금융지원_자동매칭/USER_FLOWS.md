# 사용자 흐름

## 시연자

1. 데모 컨트롤에서 시나리오를 고른다.
2. 운영자 화면에서 공지 분석과 승인을 시연한다.
3. 고객을 선택하고 게시 확인을 거쳐 앱 안내를 게시한다.
4. 데모 컨트롤로 고객 앱을 연다.
5. 고객 피해내용 확인과 신청서 제출을 시연한다.
6. 운영자 화면으로 돌아와 은행 접수와 심사 이관을 시연한다.

## 은행 담당자

1. 사건·기한·출처를 확인한다.
2. AI 구조화 결과와 원문 근거를 검토한다.
3. 결과를 승인해 고객 매칭을 시작한다.
4. 검색·필터·정렬로 우선 고객을 찾는다.
5. 고객별 점수 근거와 추천 지원을 검토한다.
6. 고객명·사업장·지원 3개를 확인하고 앱 안내를 게시한다.
7. 고객이 제출하면 은행 접수로 변경한다.
8. 서류와 근거를 확인해 심사부서로 이관한다.

## 피해 고객

1. 인증된 앱에서 재난지원 안내를 확인한다.
2. 안내받은 이유와 신고기한을 이해한다.
3. 검토 가능한 지원 3개의 지원내용·기한·서류를 비교한다.
4. 본인의 피해 진술을 입력하거나 수정한다.
5. AI가 정리한 피해내용을 확인한다.
6. 자동 확인된 정보와 직접 준비할 서류를 구분한다.
7. 신청서를 제출한다.
8. 은행 접수와 심사 이관 상태, 예상 처리시간과 문의처를 확인한다.

## 복구 흐름

- AI 실패: 저장 분석 사용 안내 → 다시 분석 가능
- 검색 결과 없음: 필터 초기화
- 잘못 선택한 고객: 게시 확인에서 취소
- 잘못 게시한 안내: 고객 제출 전 게시 취소
- 고객 오제출: 은행 접수 전 신청 취소
- 새로고침: 동일 고객 케이스 상태 복원
