# 한결 재난금융 지원센터 V2

## Product

재난 지원공지를 구조화하고 은행이 보유한 합성 고객·사업장·대출 정보를 규칙으로 대조해 우선 확인 고객을 찾은 뒤, 인증된 고객 앱에서 피해 확인과 신청을 시작하도록 돕는 재난금융 자동매칭 데모다.

하나의 웹사이트에서 발표하되, 데모 조작 영역과 은행 운영자 도구와 고객 앱은 서로 다른 역할과 언어를 유지한다.

## Users

- **주 사용자:** 재난지원·고객보호·여신관리 업무를 수행하는 한결은행 담당자
- **보조 사용자:** 재난 피해 가능성이 있어 인증된 은행 앱에서 지원을 확인하는 소상공인 고객
- **시연자:** 합성 시나리오와 사용자 화면을 전환하며 전체 흐름을 설명하는 발표자

## Core Outcome

- 담당자는 공식 공지를 검토·승인하고 우선 고객과 추천 근거를 확인한 뒤 정확한 고객에게 앱 안내를 게시한다.
- 고객은 안내받은 이유, 검토 가능한 지원 3개, 신청 기한, 필요한 서류를 이해하고 피해내용을 확인한 뒤 신청서를 제출한다.
- 은행은 고객 제출을 접수하고 심사부서로 이관한다. 자동 승인이나 지급은 표현하지 않는다.

## Core Flow

재난 선택 → AI 공지 구조화 → 담당자 승인 → 고객 우선순위화 → 고객별 케이스 검토 → 앱 안내 게시 → 고객 피해내용 확인 → 신청서 제출 → 은행 접수 → 심사부서 이관

## Product Boundaries

- 시연용 역할 전환·시나리오 전환·초기화·합성 데이터 표시는 데모 컨트롤에만 둔다.
- 운영자 도구에는 공지, 고객 우선순위, 추천 근거, 게시와 접수 업무만 둔다.
- 고객 앱에는 본인 지원, 기한, 서류, 동의, 제출과 진행현황만 둔다.
- 모든 고객·대출·피해정보는 합성 데이터다.
- 지원제도는 실제 제도에 기반하지만 자격과 승인 여부는 각 기관 심사를 거친다.
- AI는 공지와 고객 서술을 정해진 스키마로 구조화한다. 매칭과 상태 전환은 규칙 기반이다.
- OpenAI API 키가 없거나 호출에 실패하면 동일 스키마의 저장 분석을 사용하고 그 사실을 화면에 알린다.

## Scenarios

침수 피해 카페, 산불 피해 숙박업, 폭설 피해 시설농가 세 가지가 모두 신청 가능한 데모로 동작한다. 사건일·신고기한·납부일은 실행일 기준으로 계산해 시연 날짜가 지나도 흐름이 깨지지 않는다.

## Visual Direction

기존 Seed Design System과 “승인 가능한 재난금융 상황실”의 시각 언어를 유지한다. 깊은 청록 사건 밴드, 7단계 진행선, 차가운 운영 바닥, 현재 행동에만 쓰는 오렌지, 테두리 중심 패널을 보존한다. V2의 변화는 새 장식이 아니라 역할·데이터·행동 경계를 더 명확하게 만드는 데 집중한다.
