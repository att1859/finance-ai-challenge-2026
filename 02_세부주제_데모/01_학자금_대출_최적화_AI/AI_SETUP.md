## 검토용 FAQ 19개

아래는 server/knowledge.js의 답변 기준 전체다. 1번은 기존 시나리오 정의를 유지하며 2·3번은 사용자 확정 문구다. 실제 봇은 현재 시나리오와 함께 이를 참고한다.

### 1. 현재 중시·균형·미래 중시는 어떻게 다른가요?

현재 중시는 이번 학기 등록금 전액과 생활비 대출 한도를 활용한다. 균형은 등록금 최소 대출과 전액의 중간값을 빌리고 생활비 부족분을 한도 안에서 보완한다. 미래 중시는 등록금 부족분만 빌리고 생활비 대출은 받지 않는다. 세 안은 현재 생활비와 미래 상환부담을 비교하는 기준이며 어느 하나를 정답으로 추천하지 않는다.

### 4. 균형의 등록금은 왜 이 금액인가요?

실제 납부 등록금 T, 대출 없이 낼 수 있는 금액 A일 때 최소 대출은 T−A, 균형은 T−A/2, 현재 중시는 T다. 즉 균형은 최소액과 최대액의 중간이며 등록금 자체의 절반이 아니다. 개인 금액은 facts의 실제 납부 등록금·가용 자기자금·최소 대출·실행액을 읽어 설명한다.

### 5. 균형이면 알바를 안 해도 되나요?

균형은 희망 생활비에서 현재 월소득을 뺀 부족분의 6개월치를 생활비 대출로 보완하는 안이다. 최소 신청액·신청 단위·학기 및 누적한도가 적용되므로 항상 알바 0시간인 것은 아니다. facts의 생활비 부족분과 추가 알바 시간을 확인한다. 부족분이 0원이라도 이자·상환 차감 전 생활비 기준이며 모든 지출 충족을 보장하지 않는다. 현재 월소득이 충분하면 균형 생활비 대출은 0원일 수 있다.

### 6. 등록금 대출을 받으면 남는 돈을 생활비로 쓸 수 있나요?

### 7. 졸업까지 남은 학기만큼 계속 빌리는 계산인가요?

## Vercel에서 연결하기

키는 이미 Vercel에 등록되어 있다는 사용자 설명을 기준으로 진행한다. 키 재발급은 필요하지 않다. 공개 사이트 URL만으로 환경 변수의 값이나 유효성은 확인할 수 없다.

1. 배포 프로젝트의 Root Directory가 현행 앱 폴더(이 문서와 package.json이 있는 폴더)인지 확인한다.
2. 기존 Vercel 환경 변수 이름이 GEMINI_API_KEY이고 Production에 적용되어 있는지 확인한다. 실제 키는 소스 코드나 VITE_ 변수로 옮기지 않는다.
3. 승인받은 api/chat.js와 api/health.js를 기존 코드와 함께 배포한다. 두 파일은 server/index.js의 공통 요청 처리를 재사용한다. 별도 AI 서버를 복제하지 않는다.
4. 새 배포의 /api/health가 404 대신 JSON을 반환하고 configured가 true인지 확인한다. 이는 키 존재만 뜻한다.
5. 가상 예시를 계산한 뒤 SLOW 봇 → 연결 확인 → 동의하고 AI 설명 시작 → FAQ 질문으로 실제 Gemini 답변을 확인한다.

Vercel 함수는 공식 배포 도메인과 VERCEL_URL·VERCEL_PROJECT_PRODUCTION_URL의 정확한 호스트를 허용한다. 커스텀 도메인은 AI_ALLOWED_ORIGINS에 HTTPS 출처를 명시한다. 원문 요청 또는 Vercel이 파싱한 JSON 모두 기존 크기·스키마 검증을 거친다. 분당 20회·동시 2회 제한은 함수 인스턴스별 메모리 제한으로, 전체 프로젝트의 비용 한도나 사용자 인증을 대신하지 않는다.

## 1. 노트북에서 별도로 실행할 경우

현행 앱 폴더는 `D:\TEERA\Projects\Study\finance-ai-challenge-2026\02_세부주제_데모\01_학자금_대출_최적화_AI`다. 이 폴더에 키 입력용 `.env.local`을 준비했다. 이 앱에서 읽는 값만 확인했으며 노트북의 다른 위치나 Vercel에 저장한 키가 없다는 뜻은 아니다.

1. [Google AI Studio API keys](https://aistudio.google.com/apikey)에 사용 중인 Google 계정으로 로그인한다.
2. 사용 중인 프로젝트의 Gemini API 키를 복사한다. 새 키가 필요하면 해당 화면에서 프로젝트를 선택하고 발급한다. Google 약관 동의·결제 등록이 필요한 경우 계정 소유자가 직접 진행한다.
3. 로컬 편집기로 **현행 앱 폴더의 `.env.local`**을 연다. 저장소 루트가 아닌 `package.json`과 같은 위치다.
4. 아래 `발급받은_실제_키` 부분을 실제 값으로 바꾸고 저장한다. `.env.local.txt`가 되지 않도록 확장자를 확인한다.

```dotenv
GEMINI_API_KEY=발급받은_실제_키
AI_MODEL=gemini-3.5-flash-lite
AI_PORT=8787
AI_ALLOWED_ORIGINS=http://127.0.0.1:5175,http://localhost:5175
```

키는 채팅에 보내거나 `index.html`, `src/`, `.env.example`에 적지 않는다. `VITE_GEMINI_API_KEY`처럼 `VITE_` 접두사를 붙이지 않는다. 현재 코드가 읽는 이름은 정확히 `GEMINI_API_KEY`다. `.env.local`은 Git 제외 규칙에 포함되어 있다.

기본 모델은 공식 문서에서 확인한 `gemini-3.5-flash-lite`다. 모델 목록에 있다는 것과 내 프로젝트에서 호출 가능하다는 것은 다르다. 아래 실제 생성 테스트로 확인한다. 다른 모델을 사용 중이면 `AI_MODEL`만 해당 모델 ID로 바꾸되 `models/` 접두사는 넣지 않는다. Vertex AI 자격증명·OAuth 토큰을 이 키 칸에 넣는 방식은 지원하지 않는다.

의존성이 이미 설치되어 있다면 `npm ci`는 생략할 수 있다. `ai:check`는 기존 실행 서버와 충돌하지 않도록 임시 로컬 포트에서 API를 열고, 기본 가상 프로필을 SLOW 엔진으로 계산한 뒤 **FAQ와 시나리오를 넣어 Gemini를 한 번 호출**한다. 브라우저에 입력된 개인 정보는 읽지 않는다. 계정의 API 사용량이 소모될 수 있으며 자동 반복하지 않는다.

성공하면 다음 문구와 실제 생성된 한국어 답변이 출력된다.

```text

(균형의 등록금 산정 방식, 생활비 부족분, 한도에 따른 알바 시간 설명)
```

이 문구는 Google이 응답했고 SLOW가 응답 형식까지 읽었다는 뜻이다. 답변의 내용 정확성은 아래 질문으로 추가 확인한다. `configured: true`나 서버 실행 메시지만으로 연결 성공이라고 판단하지 않는다.

## 3. 화면과 API 서버를 함께 실행한다

기존 `npm run dev` 또는 `dev:api` 터미널이 실행 중이면 **그 터미널에서 Ctrl+C**로 종료하고 다시 실행한다. 환경 변수와 서버 FAQ 수정은 서버 재시작 후 적용된다. 브라우저 새로고침만으로 서버가 새 키를 읽지는 않는다.

```powershell
npm run dev
```

- 앱: [SLOW 로컬 화면](http://127.0.0.1:5175)
- 상태: [로컬 API 상태](http://127.0.0.1:8787/api/health)

상태 응답의 `configured`는 서버에 키가 존재하는지만 알려준다. `true`여도 잘못된 키·모델 권한·할당량 문제일 수 있다. 키 자체는 응답에 포함하지 않는다.

## 4. 패널에서 끝까지 확인한다

1. 가상 예시로 정보를 채우고 **결과 확인하기**를 누른다.
2. 오른쪽 **SLOW 봇**을 연다. 먼저 보이는 금액은 기존 엔진의 계산 결과 미리보기다.
3. **연결 확인**을 누른다. 이는 로컬 서버의 키 설정 여부 확인이다.
4. 외부 전달 안내를 읽고 **동의하고 AI 설명 시작**을 누른다.
5. 선택한 안의 요약·장점·주의점이 나오고 `Gemini 응답 확인됨` 상태가 표시되면 화면에서 실제 생성까지 성공한 것이다.
6. **세 시나리오 차이**, **균형이면 알바 0시간?**, **상환 방식 차이** 버튼 또는 직접 질문을 사용한다. Enter는 전송, Shift+Enter는 줄바꿈이다.
7. 앱의 조건이나 상세 대상을 바꾸면 이전 대화·요약을 초기화하고 새 계산 결과로 다시 설명한다.

## 5. 오류별 해결 방법

| 메시지·증상 | 확인할 내용 |
| --- | --- |
| `NOT_CONFIGURED` / AI 연결 준비 중 | 앱 폴더의 `.env.local` 존재, `GEMINI_API_KEY` 철자와 값, 저장 후 서버 재시작 |
| `PROVIDER_AUTH` | 키 유효성, 키가 속한 프로젝트, Gemini API 접근 권한·키 제한. 서버 호출이므로 브라우저 HTTP referrer 제한과 맞지 않을 수 있음. 필요한 API만 허용하는 적절한 서버용 제한을 설정 |
| `PROVIDER_MODEL` | `AI_MODEL` 오타·지원 종료·프로젝트 접근 가능 여부. 모델 ID 변경 후 재시작 |
| `PROVIDER_REQUEST` | 키·모델과 요청 형식, 지원 지역 및 해당 프로젝트 결제 필요 여부. 서버의 `responseSchema`를 지원하는 텍스트 모델 사용 |
| `PROVIDER_LIMIT` | Google 프로젝트의 요청량·토큰·일일 할당량과 결제 등급. 같은 키를 재발급하는 것만으로 프로젝트 한도가 늘지는 않음 |
| `RATE_LIMIT` | SLOW 로컬 분당 20회·동시 2회 제한. 잠시 기다린 뒤 한 번 재시도 |
| `TIMEOUT` / `PROVIDER_ERROR` | 네트워크·방화벽·Google 서비스 상태. `generativelanguage.googleapis.com` HTTPS 연결 확인 |
| `INCOMPLETE` | 출력이 잘리거나 정상 종료되지 않음. 질문을 줄여 재시도. 반복되면 모델·출력 토큰 설정 점검 |
| AI 서버에 연결하지 못했어요 | `npm run dev`가 정상 실행 중인지 확인. UI만 켠 경우 API 서버도 실행 필요 |
| Port already in use | 기존 개발 서버 터미널을 종료 후 재실행. 다른 서비스의 포트라면 `AI_PORT`를 비어 있는 값으로 바꿈 |
| 키를 바꿔도 예전 상태 | `.env.local` 수정 후 실행 프로세스를 재시작. 셸에 별도로 설정된 `GEMINI_API_KEY` 환경 변수는 `.env.local`보다 우선하므로 중복 설정 확인 |
| `ai:check` 성공, 패널 실패 | 기존 서버 재시작 여부와 Vite 프록시 확인. 화면 포트를 바꾸면 `vite.config.js`와 `AI_ALLOWED_ORIGINS`의 출처도 함께 변경 |

공급자 오류 원문에는 민감정보가 포함될 수 있어 그대로 노출하지 않는다. 오류를 공유할 때는 키 대신 위 오류 코드와 `requestId`만 사용한다.

## 6. FAQ와 시나리오가 실제로 들어가는 위치

- `server/knowledge.js`: 19개 FAQ의 질문·답·제품/정책 구분·출처·확인일. **FAQ 수정의 단일 기준 파일**이다. 사진의 정의를 프로젝트 코드와 대조하고 한국장학재단 공식 자료를 추가 조사했다.
- `src/app/ai-context.js`: 선택안과 비교안의 계산 결과를 단위 있는 facts로 변환한다. 등록금·자기자금·생활비·알바 시간·상환 및 자격 상태를 보낸다. 프로필 전체와 월별 원장은 보내지 않는다.
- `server/ai-provider.js`: 서버 FAQ를 `systemInstruction`에, facts와 최근 대화를 `contents`에 넣어 Gemini `generateContent`를 호출한다. 개인 수치는 엔진의 facts만 설명하고 임의 재계산하지 않게 지시한다.
- `server/index.js`: 입력 검증과 로컬 요청 제한, `/api/health`, `/api/chat`, `--check` 진단을 담당한다.
- `src/app/ai-session.js`: 동의·대화·취소·재시도·조건 변경 후 이전 응답 폐기를 담당한다.

현재 FAQ 양은 요청마다 전체를 포함할 수 있는 규모이므로 기존 지식 모듈을 사용한다. 외부 검색 DB나 별도의 업로드 절차는 없다. 봇이 매번 웹을 검색하는 기능도 아니다. 정책이 바뀌면 공식 자료와 엔진 정책 스냅샷을 함께 확인해 FAQ를 갱신하고 서버를 재시작한다. 사진·웹페이지의 대화나 지시는 실행 명령으로 가져오지 않았다.

## 7. 데이터와 배포 경계

API 키는 서버에서만 Google 헤더로 전송한다. 대화는 브라우저 메모리에 유지하며 SLOW 서버에 영구 저장하지 않는다. Google 처리에는 제공사의 약관이 적용된다. `store:false`는 요청 로깅 설정이며 제공사의 모든 보관이 없다는 보장은 아니다. 실제 개인 정보 사용 전 [서비스 약관](https://ai.google.dev/gemini-api/terms)과 [요금·데이터 사용 안내](https://ai.google.dev/gemini-api/docs/pricing)를 확인한다.

로컬 서버와 Vercel 함수는 같은 처리 코드를 사용한다. `dist`만 올리면 AI 함수는 포함되지 않으므로 앱 소스의 api/ 파일도 함께 배포해야 한다. 공개 서비스의 사용자 인증·프로젝트 전체 사용량 통제는 별도이며 현재 제한은 인스턴스별이다.
