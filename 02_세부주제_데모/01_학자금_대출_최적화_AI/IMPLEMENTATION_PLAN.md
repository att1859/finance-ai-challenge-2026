# 학자금 소비평탄화 AI 개편 실행계획

이 문서는 개편 목표와 작업 상태를 관리하는 단일 실행 기준이다. `PRODUCT.md`는 현재 구현 상태를 설명하고, 이 문서는 앞으로 바꿀 목표 상태를 설명한다. 3번과 4번의 상세 계산·판정 기준은 `LOAN_SCENARIO_REDESIGN_SPEC.md`에 기록한다. 작업이 완료되면 같은 작업 안에서 코드, 테스트, `PRODUCT.md`, 관련 용어·구조 문서, 이 문서의 상태와 변경 기록을 함께 갱신한다.

## 작업 운영 규칙

1. 작업을 시작하기 전에 `PRODUCT.md`, `CONTEXT.md`, `ARCHITECTURE.md`, `DESIGN.md`, 이 문서와 `LOAN_SCENARIO_REDESIGN_SPEC.md`를 읽는다.
2. 한 번에 하나의 작업 ID만 `진행 중`으로 바꾼다.
3. 코드를 수정하기 전에 해당 작업의 수용 조건과 영향 범위를 확인한다.
4. 구현과 관련 검증이 모두 끝난 경우에만 `완료`로 바꾼다.
5. 요구사항이 달라지면 코드를 먼저 바꾸지 않고 이 문서를 먼저 수정한다.
6. 각 작업을 마칠 때 하단 변경 기록에 날짜, 작업 ID, 검증 결과를 남긴다.

### 상태값

- `미착수`: 아직 시작하지 않음
- `진행 중`: 현재 구현 중인 유일한 작업
- `검증 필요`: 구현은 끝났지만 테스트 또는 화면 검수가 남음
- `완료`: 수용 조건과 검증을 모두 통과함
- `보류`: 요구사항은 유지하되 현재 개편 범위에서는 구현하지 않음
- `검토`: 구현 여부나 연결 방식이 아직 확정되지 않음

## 확정된 제품 기준

- 금리·한도·자격·상환 기준은 계산 기준 학기의 버전형 로컬 정책 스냅샷에서 가져오며, 2026학년도 2학기 최초 스냅샷의 금리는 일반 상환 고정 1.7%, 취업 후 상환 변동 1.7%다.
- 대학 시절 월 희망 생활비 기본값은 80만 원이다.
- 등록금은 장학금·감면이 반영된 학기당 실제 납부액과 학기당 대출 없이 낼 금액을 따로 받고, 후자를 모든 시나리오에서 먼저 차감한다.
- 최초 입력에서는 현재 주당 근로시간만 받으며 희망 주당 근로시간은 받지 않는다.
- 근로시간에 따라 주휴수당과 선택한 세금 추정률을 자동 계산한다.
- 세금 추정률 기본값은 `3.3%`이며 선택 옵션은 `4대보험 9.5%`, `일용근로 0%`다.
- 미래 임금·생활비·취업 후 상환기준소득·변동금리의 상승폭을 예측하지 않고 계산 시점의 현재가치와 정책값을 유지한 `현재 기준 10년 단순 비교`를 제공한다.
- 일반 상환·취업 후 상환과 등록금·생활비를 네 계산 조합으로 분리하고, 자격·한도·특례·실행·상환을 상품과 용도별로 판정한다.
- 최소대출안은 현재 근로시간에서 필요한 최소 대출, 균형안 v1은 최대 근로시간 감소 효과의 50%, 최대활용안은 희망 생활비를 넘는 초과 대출 없이 가능한 최대 근로시간 감소를 계산한다.
- 공식 한도까지 받는 경우는 추천안이 아니라 `풀대출 상한 보기`로 분리한다.
- 일반 상환 비교는 원리금균등으로 통일하고 졸업 후 준비기간 기본 1년, 상환기간 기본 10년을 사용한다.
- 대출상품, 생활비 대출, 일반 상환 준비·상환기간과 자격 특례조건은 최초 입력이 아니라 시나리오 결과에서 필요한 경우에만 선택한다.
- 확정적으로 불가능한 후보만 제외하며, 조건부·정보부족 후보는 필요한 조건을 확인한 뒤 다시 계산한다.
- 추천은 자격·안전·충족·시나리오 목표 규칙을 먼저 적용하고 같은 규칙 등급의 후보에만 내부 점수를 사용한다. 점수는 사용자에게 표시하지 않는다.
- 장학금과 지원사업 기능 및 결과 섹션은 제거한다.
- 기존 소비평탄화 교육 설명창의 구성과 문구는 이번 개편에서 변경하지 않는다.
- 2차원 시나리오 그래프와 그래프 인접 상환액 차이는 이번 실행에서 보류한다.

## 디자인 고정 규칙

- `DESIGN.md`와 현재 화면을 시각 기준으로 고정한다.
- 일반 기능 작업에서는 색상, 글꼴, 간격 체계, 모서리 체계, 전체 레이아웃 문법을 새로 만들지 않는다.
- 새 UI는 기존 토큰, 버튼, 입력 행, 비교 원장, 규칙선을 재사용한다.
- 사용자가 별도로 재디자인을 요청하지 않는 한 Impeccable은 기존 디자인을 보존하는 정제·접근성·반응형 검수에만 사용한다.
- `redesign`, `bolder`, `colorize`, 새로운 시각 세계 선택은 별도 사용자 승인 없이는 실행하지 않는다.
- 화면 검수에서 발견한 문제는 현재 디자인 안에서 수정하며, 검수를 이유로 새로운 디자인 방향을 도입하지 않는다.
