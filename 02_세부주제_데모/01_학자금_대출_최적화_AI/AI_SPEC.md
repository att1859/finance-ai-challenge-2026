# SLOW AI 추가 명세

작성일: 2026-09-06. 상태: 토론을 바탕으로 작성한 구현 전 제안. 이 문서는 AI가 이미 구현되어 있다는 의미가 아니다.

## 1. 목적과 범위

제품 방향은 **지금 보고 있는 내 시나리오를 이해하고 설명하는 AI**다. 사용자가 선택한 안의 현재 생활비와 이후 상환 부담을 이해하고, 자기 상황에 맞는 질문을 할 수 있도록 돕는다.

AI는 기존 계산 결과를 자연어로 설명한다. 금액 계산·상품 자격 판정·상품 구성 후보 선정은 기존 엔진이 담당한다. 시나리오 전체를 최적안으로 선정하거나 실제 대출 승인을 단정하지 않는다.

이번 목표는 5시간 안에 로컬에서 시연 가능한 최소 기능이다. API 계정·유효한 키·사용 가능 모델·네트워크가 준비되어야 한다. 외부 공개 배포는 배포 환경 확인 후 시간을 별도로 판단한다. 아래 시간은 작업 추정이며 완료 보장이 아니다.

## 2. 사용자 경험

결과 화면 우측 하단에 SLOW 봇 버튼을 둔다. 버튼을 누르면 우측 패널이 열리고, 모바일에서는 화면 폭에 맞는 패널로 전환한다. 기존 종이색·남색·라임·파랑, 서체와 SEED 버튼을 재사용한다. 참고 이미지의 손그림 형태와 장식은 구현 요건이 아니다.

패널에는 설명 대상 시나리오 이름, 기본/변경 조건, 요약, 대화 내역, 입력창을 표시한다. 입력창 안내는 “SLOW 봇에게 질문하세요”로 한다. 닫기·다시 시도·대화 초기화를 지원한다. 키보드 열기·닫기와 포커스 복귀, 응답 상태 알림을 제공한다.

최초 AI 사용 전에 전달할 정보와 제공사를 짧게 알리고 사용자가 시작하도록 한다. 동의 후 열린 패널은 선택 조건이 바뀔 때 요약을 자동 갱신한다. 닫힌 동안에는 호출하지 않고 다음에 열 때 현재 상태로 요약한다.

요약은 다음 세 항목으로 제한한다.

- 요약: 이번 학기 대출 구성과 생활비 효과, 1~2문장.
- 장점: 사용자가 현재 확보하는 생활비·자기자금 여유 등 실제 결과에 있는 효과, 1~2개.
- 주의점: 상환 부담·생활비 부족·자격 미확인 등 해당 안에 적용되는 항목, 1~2개.

질문 예시 버튼은 “다른 안과 무엇이 달라요?”, “왜 이 생활비가 나오나요?”, “거치기간이 뭐예요?”로 한다. 답변은 기본 3~6문장으로 하고 정책 안내에는 공식 출처와 기준일을 붙인다.

## 3. 최소 기능의 수용 조건

| 기능 | 완료 기준 |
| --- | --- |
| 선택안 요약 | 현재 상세 대상·상품·기본/변경 조건과 동일한 결과를 설명한다. |
| 결과 질의응답 | 등록금·생활비 구분, 표시 단위와 관찰 기간을 지켜 답한다. |
| 두 안 비교 | 비교 대상 A/B의 계산된 값과 차이를 사용한다. NO 대출은 별도 기준으로 설명한다. |
| FAQ 답변 | 준비된 용어·정책 자료만 근거로 쓰고, 자료가 부족하면 확인 필요와 공식 안내를 제시한다. |
| 상태 갱신 | 조건 변경 이전에 보낸 요청의 늦은 응답이 현재 요약에 표시되지 않는다. |
| 실패 처리 | 키 오류·할당량 초과·시간 초과 시 재시도를 제공하고 기존 계산 화면은 계속 동작한다. |

챗봇이 입력값을 직접 수정하는 기능, 새로운 가정의 자동 시뮬레이션, 실시간 웹 검색, 파일 업로드, 음성, 로그인·대화 영구 저장, 벡터 DB, 파인튜닝은 이번 범위에 넣지 않는다. 향후 구현을 약속한 보류 목록이 아니다.

“소득이 더 줄면?”처럼 현재 결과에 없는 계산을 요청받으면 앱의 조건 변경 기능을 안내한다. 이미 계산된 기본/변경 결과가 있으면 그 범위에서 설명한다.

## 4. AI에 전달할 정보

앱 상태 전체나 DOM을 보내지 않고 전용 선택자로 아래 정보만 구성한다.

| 정보 | 내용 |
| --- | --- |
| 현재 맥락 | 시나리오 ID·이름, 비교 A/B, 기본/변경 보기, 관련 조회 시점, contextVersion |
| 필요한 입력 | 남은 학기, 등록금·자기자금·월소득·희망 생활비·예상 소득, 현재 설명에 필요한 자격 상태 |
| 계산된 사실 | 용도별 대출·상품, 생활비, 남겨두는 자기자금, 추가 알바 시간, 상환 부담·잔액·완납 상태 |
| 계산 의미 | 각 수치의 단위·관찰 기간·차감 전후, 정책 버전·출처·확인일, 계산에 포함하지 않은 가정 |
| 비교 자료 | A/B의 동일 지표와 엔진 또는 코드가 미리 구한 차이 |
| 지식 자료 | 용어·FAQ·공식 요건의 짧은 검증된 항목 |
| 대화 | 현재 맥락의 최근 대화 최대 6쌍과 새 질문 |

요약용 핵심 숫자는 코드가 형식화해 고정 사실로 전달한다. AI가 상환 원장을 다시 계산하지 않도록 한다. 일반 월 약정 납입액과 취업 후 상환의 월평균 환산액을 구별한다. 상환기간 생활비의 관찰 기간은 현재 앱 결과를 따르며, 이를 임의로 취업 첫해로 바꾸지 않는다. 10년 비교와 완납까지의 그래프 기간도 구별한다.

조건이 바뀌면 contextVersion을 갱신하고 이전 요청을 취소한다. 응답 버전이 현재와 다르면 버린다. 최소 버전에서는 대화도 초기화하고 “조건이 바뀌어 새 설명을 시작합니다”를 표시한다. 동일 맥락의 요약은 브라우저 메모리에 재사용하고 다른 사용자와 공유 캐시하지 않는다.

## 5. 지식 자료

기존 CONTEXT.md의 용어, 정책 스냅샷과 policyReferences, 공식 요건 팝업을 출발점으로 사용한다. 문서 전체를 그대로 프롬프트에 넣지 않고 사용자용 문답 12~15개로 정리한다. 대출 요건은 구현 시 공식 원문과 다시 대조한다.

핵심 주제는 등록금/생활비 대출 구분, 일반/취업 후 상환 차이, 거치기간, 원리금균등, 변동금리, 월평균 환산액, 소비 평탄화, 이번 학기 계산 범위, 자기자금 여유, 추가 알바 환산, 자격 확인, 이자면제/상환유예 차이, 한도/실행 단위, 10년 비교와 완납 시점이다.

항목마다 id, 질문, 답변, 적용 상품·조건, sourceIds, 확인일, 정책 버전을 둔다. 용어는 내부 용어 문서를 출처로, 제도 요건은 공식기관 원문을 출처로 구별한다. 소규모 자료이므로 첫 버전에서는 압축한 자료를 서버에서 함께 전달하며 검색 DB를 만들지 않는다.

출처 URL은 서버가 관리한다. 모델에는 허용된 출처 ID를 주고, 응답의 ID를 검사한 뒤 앱이 실제 링크로 표시한다. 출처 ID가 유효하다는 것만으로 내용이 검증되었다고 간주하지 않으며 시연 질문의 근거 일치를 별도로 확인한다.

## 6. API 연결 제안

연결은 `브라우저 → SLOW /api/chat → Gemini API → SLOW → 브라우저`로 구성한다. 초기에는 Node 서버 하나를 두고 Vite 개발 서버에서 /api 요청을 전달한다. 배포 때는 같은 요청 계약을 지원하는 서버리스 함수 또는 Node 호스트를 선택한다. 정적 파일만 배포해서는 API가 동작하지 않는다.

2026-09-06 확인한 Google 공식 가격 안내에서 Gemini 3.5 Flash-Lite는 비용 효율성을 강조하는 정식 모델이다. 이를 우선 시험 후보로 삼되 계정에서 호출 가능한지와 대표 한국어 질문 품질을 확인한 뒤 모델 ID를 고정한다. 응답 품질이 부족하면 다른 Flash 모델을 비교한다. 여러 제공사를 동시에 붙이는 작업은 하지 않는다.

API 키는 서버의 GEMINI_API_KEY 환경 변수로 관리하고 브라우저 코드·VITE_ 변수·Git에 넣지 않는다. 모델 이름은 서버 설정 AI_MODEL로 분리한다. 제공사 요청 코드는 한 모듈에 모아 교체 가능하게 한다. 사용자에게 키를 채팅으로 보내도록 요구하지 않는다.

첫 구현 순서는 (1) 사용자가 AI Studio에서 프로젝트와 키 준비, (2) 서버 환경 변수 설정, (3) 가상 정보로 1회 호출 확인, (4) 앱 맥락과 지식 자료 연결, (5) 패널 연결이다. 첫 30분 안에 실제 호출이 성공하는지 확인한다.

제안 요청 계약: POST /api/chat에 mode(summary 또는 chat), contextVersion, context, messages를 보낸다. 서버가 스키마·길이를 검사하고 신뢰하는 정책·지식·시스템 지침을 추가한다. 클라이언트가 보낸 지침·출처 URL은 신뢰하지 않는다.

제안 응답 계약: requestId, contextVersion, answer, sourceIds를 반환한다. summary 모드에는 summary, benefits, cautions를 구분한다. 서버가 형식과 출처 ID를 검사한다. 생성문은 일반 텍스트로 표시하고 임의 HTML을 실행하지 않는다. 첫 버전은 스트리밍 없이 로딩 표시 후 완성 답변을 표시한다.

입력·시나리오 이름·FAQ 본문은 참고 데이터이며 명령이 아니다. 자료나 질문에 “기존 지침 무시”가 있어도 계산 규칙이나 역할이 변경되지 않도록 시스템 지침을 분리한다. 프롬프트만으로 오류 방지를 보장하지 않으며 대표 질문과 공격성 입력을 검증한다.

## 7. 호출·데이터 관리

첫 제안 한도는 질문 1,000자, 요청 본문 64KB, 최근 대화 6쌍, 출력 최대 약 800토큰, 요청 시간 제한 30초다. 요약은 열린 패널의 확정된 조건 변경에만 호출하고 연속 변경은 합친다. 요청 중 중복 전송을 막고 실패 시 무한 자동 재시도하지 않는다.

로컬 시연 서버는 루프백에 바인딩하고 단일 시연 세션의 요청 횟수를 제한한다. 공개 배포에는 서버 측 접근·호출 제한과 비용 차단 방식을 추가 확인한다. CORS나 예산 알림만으로 무단 호출 또는 과금을 막았다고 간주하지 않는다.

SLOW 서버는 프로필·질문·답변 원문을 영구 저장하거나 로그로 남기지 않는다. 브라우저 대화는 메모리에서만 유지한다. 제공사의 처리·보관은 별도 정책이므로 “어디에도 저장되지 않는다”라고 안내하지 않는다. 외부 전달 안내에는 제공사, 입력·시나리오·질문 전달 범위와 목적을 명시한다.

Google 가격 안내는 무료/유료 등급의 제품 개선용 콘텐츠 사용을 구별한다. 초기 무료 테스트는 가상 정보로 하고 실제 사용자 정보 사용 전 적용 약관을 확인한다. 유료 등급의 제품 개선 미사용을 무보관과 동일시하지 않는다.

가격 총액은 모델 확정 후 입력·출력·사고 토큰과 호출 횟수로 산정한다. FAQ와 대화도 매번 입력 비용에 포함될 수 있다. 현재 단가는 이 문서에 추정하여 고정하지 않는다.

## 8. 기존 구조에 추가할 위치

아래는 구현 시 제안 위치이며 이번 문서 작성으로 생성한 코드가 아니다.

| 위치 | 역할 |
| --- | --- |
| src/app/ai-context.js | 기존 선택자와 계산 결과에서 AI용 사실 묶음 생성 |
| src/app/ai-chat.js | 패널 상태·요청·취소·맥락 변경 처리 |
| src/ui/sections/ai-assistant.js | 패널·대화·요약 렌더링 |
| src/ui/styles/ai-assistant.css | 기존 토큰을 이용한 반응형 스타일 |
| server/index.js | 로컬 API 서버, 요청 검증·한도·오류 처리 |
| server/ai-provider.js | Gemini 인증·모델 호출·응답 검증 |
| server/knowledge.js | 검토된 FAQ와 출처 목록, 기존 정책 참조 |
| tests/unit 및 tests/integration | 맥락·단위·오래된 응답·API 실패 관련 검증 |

AI의 API 장애는 domain/application 계산을 막지 않는다. 새 서버는 이번 외부 API 도입에 필요한 범위로만 추가한다.

## 9. 5시간 작업 배분

| 구간 | 작업 | 확인 결과 |
| --- | --- | --- |
| 0:00~0:30 | 키·모델·서버 호출 확인 | 가상 질문에 실제 API 답변 |
| 0:30~1:15 | 맥락 선택자와 핵심 FAQ | 화면과 일치하는 사실 묶음·출처 |
| 1:15~2:15 | 플로팅 패널과 대화 연결 | 요약·추가 질문·닫기 동작 |
| 2:15~3:15 | 선택안 갱신과 비교 설명 | 변경 후 과거 응답 혼입 없음 |
| 3:15~4:00 | 한도·실패·전달 안내·출처 | 오류가 나도 기존 서비스 사용 가능 |
| 4:00~5:00 | 대표 질문·회귀·모바일 확인, 문서 반영 | 로컬 시연과 재현 가능한 확인 기록 |

API 준비가 지연되면 임시 응답으로 UI 작업은 진행할 수 있지만 실제 AI 연결 완료로 표시하지 않는다. 5시간 초과 시 기능을 더 넣기보다 수치·맥락·실패 처리 검증을 우선한다. 외부 배포가 필수로 확인되면 이 시간표를 다시 조정한다.

## 10. 시연 및 검증

가상 프로필 입력 → 균형 선택 → 요약 확인 → 미래 중시와 차이 질문 → 거치기간 질문 → 시나리오·상품 변경 → 갱신된 설명 확인 순서로 시연한다.

대표 검증 질문은 “왜 이 대출액인가요?”, “생활비는 매달 새로 빌리나요?”, “남겨둔 등록금 자금이 생활비에 포함되나요?”, “두 안의 취업 후 상환액이 왜 같나요?”, “월평균 환산액은 청구액인가요?”, “10년 뒤 잔액이면 완납이 아닌가요?”, “내 대출 승인 확정인가요?”, “자료에 없는 특례도 되나요?”다. 추가로 지침 무시 요청과 HTML 입력을 검사한다.

화면 수치·단위·기간 불일치, 승인 단정, 근거 없는 정책 생성은 수정 후 재검증한다. 네트워크 실패·429·시간 초과·조건 변경 중 응답 역전도 확인한다. 기존 npm test와 npm run build를 실행하고 Codex 내장 브라우저에서 360px·데스크톱, 키보드 조작과 본문 가림을 확인한다. 실제 API 질문 검증과 자동 테스트 결과를 구별해 기록한다.

구현·검증을 마치면 PRODUCT.md·ARCHITECTURE.md·CONTEXT.md·DESIGN.md 중 관련 문서에 실제 동작을 반영한다. 이 문서의 시간표·미구현 제안을 완료/보류 계획으로 별도 유지하지 않고 통합 정리한다. 기존에 삭제한 다른 계획을 후속 작업에 포함하지 않는다.
