# 대출 모델·시나리오 계산 개편 상세 명세

## 문서 역할

이 문서는 `IMPLEMENTATION_PLAN.md`의 3번 대출 모델 개편과 4번 시나리오 계산 개편을 구현하기 위한 목표 상태 상세 명세다. 2026-09-01까지 사용자와 합의한 입력, 정책 경계, 계산식, 추천 규칙, 결과 흐름과 보류 범위를 기록한다.

- `IMPLEMENTATION_PLAN.md`: 작업 순서, 상태, 수용 조건의 단일 기준
- 이 문서: 아직 구현되지 않은 목표 상태의 상세 계산·판정 기준
- `PRODUCT.md`: 현재 동작하는 제품 범위
- `CONTEXT.md`: 현재 구현에서 사용하는 용어
- `ARCHITECTURE.md`: 현재 구현 구조와 의존 방향

구현 전에는 이 문서를 현재 기능 설명으로 인용하지 않는다. 작업 ID가 구현·검증까지 완료되면 같은 작업에서 `PRODUCT.md`, `CONTEXT.md`, `ARCHITECTURE.md`의 해당 내용을 목표 상태에 맞게 갱신한다. 요구사항이 충돌하면 `IMPLEMENTATION_PLAN.md`의 최신 결정과 이 문서의 상세 규칙을 우선하고, 코드 변경 전에 두 문서를 먼저 일치시킨다.

## 1. 확정 범위

### 1.1 최초 입력

최초 입력에서 다음 정보를 받는다.

- 학기당 실제 납부 등록금
- 학기당 대출 없이 낼 등록금
- 학자금 지원구간
- 남은 재학기간
- 월 희망 생활비
- 현재 주당 근로시간, 시급, 간편 차감방식
- 취업 후 예상 월소득의 현재가치

`학기당 실제 납부 등록금`은 장학금과 등록금 감면이 이미 반영된 고지서 금액이다. `학기당 대출 없이 낼 등록금`은 부모 지원, 저축 등 실제로 등록금에 투입할 금액이며 모든 시나리오에서 먼저 차감한다.

```text
0 <= 학기당 대출 없이 낼 등록금 <= 학기당 실제 납부 등록금
학기당 등록금 대출 필요액
= max(0, 학기당 실제 납부 등록금 - 학기당 대출 없이 낼 등록금)
```

두 등록금 입력값은 별도 변경이 없는 한 남은 모든 학기에 동일하게 적용한다.

최초 입력에서는 다음 정보를 받지 않는다.

- 일반 상환·취업 후 상환 선택
- 생활비 대출 이용 여부
- 원금균등·원리금균등 선택
- 자격·이자·상환 특례의 세부조건
- 기존 학자금대출 잔액
- 미래 임금상승률과 물가상승률

### 1.2 현재 기준 10년 단순 비교

미래 급여, 생활비, 취업 후 상환기준소득의 상승폭을 예측하지 않는다. 모든 비교값은 계산 시점의 현재가치와 정책 스냅샷을 유지한다.

```text
취업 후 월소득(t) = 입력한 취업 후 예상 월소득
희망 월생활비(t) = 입력한 월 희망 생활비
취업 후 상환기준소득(y) = 계산 기준연도의 공식값
대출금리(t) = 계산 기준 학기의 공식값
비교기간 = 취업 후 120개월
```

결과 명칭은 `현재 기준 10년 단순 비교`로 통일한다. 실제 미래값을 예측하거나 확정하는 표현을 사용하지 않는다. 과거에 검토한 임금상승률 3.3%와 생활비 상승률 3.12%는 입력, 계산, 설정에서 사용하지 않는다.

초봉 20% 감소 스트레스는 취업 후 월소득을 기준안의 80%로 낮춘 뒤 120개월 동안 같은 현재가치로 유지한다.

## 2. 대출 도메인 모델

### 2.1 상품과 용도 분리

법적 상환상품 2종과 자금용도 2종을 조합한 네 계산 단위를 독립적으로 판정한다.

| 상품 | 등록금 | 생활비 |
|---|---|---|
| 일반 상환 | 별도 자격·한도·실행·상환 일정 | 별도 자격·한도·실행·상환 일정 |
| 취업 후 상환 | 별도 자격·한도·이자면제·의무상환 | 별도 지원구간·예외·한도·이자면제·의무상환 |

단일 `newLoan`을 계산의 원장으로 사용하지 않는다. 목표 결과 계약은 다음 책임을 가진다.

```text
loanComposition
├─ tuitionComponents[]
│  ├─ product
│  ├─ principal
│  ├─ semester
│  ├─ disbursementDate
│  ├─ eligibility
│  └─ policyReference
└─ livingComponents[]
   ├─ product
   ├─ principal
   ├─ semester
   ├─ disbursementDate
   ├─ eligibility
   └─ policyReference
```

동일 학기의 등록금과 생활비에 서로 다른 상품을 조합하는 혼합 구성은 공식 실행규정으로 허용이 확인된 조합만 후보로 생성한다. 확인되지 않은 혼합 구성은 `unknown`으로 남기고 추천하지 않는다.

`DATA-01` 공식 확인 결과 등록금과 생활비는 별도 실행되고 일반 상환에서 취업 후 상환으로의 전환도 등록금·생활비를 각각 또는 함께 처리할 수 있다. 따라서 `일반 등록금+일반 생활비`, `일반 등록금+취업후 생활비`, `취업후 등록금+일반 생활비`, `취업후 등록금+취업후 생활비` 네 조합을 각 구성요소가 개별 자격을 충족할 때 후보로 허용한다. 같은 용도에 두 상품을 임의로 합산한 후보는 생성하지 않으며, 해당 학기 전환 과정에서 남은 계좌는 공식 공통 한도 안의 별도 실행분으로만 추적한다.

### 2.2 자격 상태

자격 판정 상태는 다음 네 값으로 고정한다.

- `eligible`: 현재 입력과 정책 기준으로 자격요건 충족
- `conditional`: 특정 조건 확인 결과에 따라 가능 여부가 달라짐
- `ineligible`: 현재 입력만으로 명확하게 불가
- `unknown`: 판정에 필요한 정보 또는 공식 규칙이 부족함

`ineligible`만 추천 후보에서 제거한다. `conditional`과 `unknown`은 후보를 유지하되 추천 배지를 붙이지 않고, 결과에서 필요한 조건을 확인한 뒤 다시 판정한다. 제외된 조합은 기본 카드에서 숨기되 `제외된 선택지와 이유`에서 확인할 수 있게 한다.

### 2.3 자격과 특례 분리

특례를 하나의 불리언 값으로 합치지 않는다.

```text
eligibilityOverrides[]
interestExemptions[]
repaymentDeferrals[]
```

각 규칙은 적용 상품, 자금용도, 대상조건, 효력 시작일·종료일, 판정상태, 공식 출처를 보존한다. 생활비 지원구간 예외와 대출 후 이자면제·의무상환 유예를 서로 대체하지 않는다.

### 2.4 2026학년도 2학기 초기 정책 스냅샷 경계

초기 구현 스냅샷 ID는 `kosaf-2026-2`, 효력 시작일은 2026-07-01, 공식 확인일은 2026-09-01이다. 원본은 `src/policies/loans/2026-2.js`에 읽기 전용 로컬 데이터로 보존하고 런타임 외부 API를 호출하지 않는다.

초기 스냅샷은 다음 공식 경계를 표현할 수 있어야 한다. 값은 코드에 흩어 쓰지 않고 정책 파일에서만 제공한다.

- 일반 상환 등록금·생활비: 학자금 지원구간 제한 없음
- 취업 후 상환 등록금: 학부·대학원 지원구간 제한 없음
- 취업 후 상환 생활비: 학부 8구간 이하, 대학원 6구간 이하가 기본

- 일반 상환 기본 연령: 만 55세 이하, 공식 계속재학 특례는 별도 규칙

- 일반 상환 재학생: 직전학기 70/100점 및 원칙적으로 12학점

## 3. 세 시나리오 계산

### 3.1 공통 계산 단위

- 남은 재학기간은 0.5년 단위이며 한 학기는 6개월로 계산한다.
- 등록금과 생활비 대출은 학기별 실행분으로 생성한다.
- 월 근로소득은 기존 주휴수당·간편 차감 규칙을 그대로 사용한다.
- 근로시간 후보는 0시간부터 현재 주당 근로시간까지 0.5시간 단위로 탐색한다.
- 주 15시간 주휴수당 경계 때문에 대출액과 근로시간의 관계를 단순 비례식으로 계산하지 않는다.
- 생활비 대출 신청액은 공식 최소액과 신청 단위를 만족하도록 조정하고 조정 전 필요액과 차이를 계산 흔적에 남긴다.

학기 `s`에서 주당 근로시간 `h`를 유지하는 데 필요한 생활비 대출은 다음 구조로 계산한다.

```text
학기 생활비 필요액(s) = 월 희망 생활비 × 학기 대상 개월 수
학기 근로소득(s, h) = 월 예상 실수령 근로소득(h) × 학기 대상 개월 수
학기 생활비 대출 필요액(s, h)
= max(0, 학기 생활비 필요액(s) - 학기 근로소득(s, h))
```

공식 학기 한도를 넘는 금액은 대출에 포함하지 않고 `unmetLivingGap`으로 남긴다.

### 3.2 최소대출안

- 현재 주당 근로시간을 유지한다.
- 등록금은 비대출 납부액을 차감한 부족분만 대출한다.
- 생활비는 현재 근로소득으로 채우지 못하는 금액만 대출한다.
- 부족분이 없으면 생활비 대출은 0원이다.

### 3.3 균형안 v1

균형안은 경제적 최적점을 의미하지 않는다. 현재 개편에서는 최대활용안이 줄일 수 있는 근로시간의 50% 지점을 임시 정책으로 사용한다.

```text
최대 근로시간 감소량 = 현재 근로시간 - 최대활용안 근로시간
균형안 목표 감소량 = 최대 근로시간 감소량 × 0.5
균형안 목표 근로시간 = 현재 근로시간 - 균형안 목표 감소량
```

목표 근로시간은 0.5시간 단위로 조정하고, 그 시간을 유지하며 희망 생활비를 충족하는 최소 생활비 대출을 역산한다. 규칙과 명칭에는 `v1`을 보존하고 추천 모듈만 교체해 후속 개선할 수 있게 한다.

### 3.4 최대활용안

공식 생활비 대출 한도 안에서 희망 생활비를 유지할 수 있는 가장 낮은 근로시간을 찾는다. 그 근로시간을 달성하는 데 필요한 금액만 빌린다.

```text
feasibleHours
= 생활비 대출 필요액(s, h)이 모든 학기의 공식 한도 안인 h 후보

최대활용안 근로시간 = min(feasibleHours)
최대활용안 생활비 대출
= 최대활용안 근로시간에서 필요한 학기별 생활비 부족분
```

희망 생활비와 근로시간 감소에 기여하지 않는 초과 대출은 추천 구성에 포함하지 않는다. 공식 한도 전액을 받는 경우는 `풀대출 상한 보기`로 별도 계산하며 추천 배지를 붙이지 않는다.

최대 근로시간 감소량이 0이면 균형안과 최소대출안의 중복 여부를 판정해 같은 결과 카드를 반복하지 않는다.

## 4. 상환 계산

### 4.1 일반 상환

- 서비스 비교 방식은 원리금균등으로 통일한다.
- 실제 상품에 원금균등 선택지가 있다는 사실은 안내하되 이번 실행에서 계산 옵션으로 제공하지 않는다.
- 각 학기 등록금·생활비 실행분을 별도 대출로 계산한 뒤 같은 달의 납입액과 잔액을 합산한다.
- 거치 중에는 실행분별 이자만 납부한다.
- 졸업 후 준비기간 기본값은 1년이며 결과에서 0년·1년·2년을 선택할 수 있다.
- 상환기간 기본값은 10년이며 공식 허용 범위 안에서 연 단위로 변경할 수 있다.
- 학제와 나이로 계산한 공식 최장 거치·상환기간을 넘을 수 없다.

실행분의 기본 거치기간은 다음 구조를 따른다.

```text
기본 거치기간
= ceil(실행 시점부터 예정 졸업까지 남은 개월 수 / 12)
 + 졸업 후 준비기간
```

일반 상환은 실제 취업 여부와 무관하게 약정한 일정에 따라 시작한다. 취업 지연은 일반 상환 시작일을 자동으로 옮기지 않는다.

졸업 1년 지연 스트레스에서는 이미 실행된 대출의 약정을 변경하지 않는다. 지연으로 발생한 추가 학기의 등록금·생활비 대출만 새 실행분으로 추가하며, 기존 거치기간이 먼저 끝나면 재학 중 상환 부담을 그대로 표시한다.

### 4.2 취업 후 상환

- 고정 상환기간이나 원리금균등 방식으로 표현하지 않는다.
- 취업 후 10개 연도의 연간 의무상환액, 납부이자와 연말 잔액을 계산한다.
- 기준소득 이하이면 의무상환액이 0원일 수 있다.
- 의무상환액이 0원이더라도 남은 잔액과 발생이자를 숨기지 않는다.
- 이자면제는 자격 판정과 분리해 적용기간과 대상 원금을 계산한다.
- 현재 정책값을 10년 동안 유지하므로 결과를 실제 미래 상환액으로 표현하지 않는다.

월 단위 비교가 필요한 텍스트에서는 연간 의무상환액을 12로 나눈 `월평균 환산액`임을 명시하며 실제 월별 청구액이라고 표현하지 않는다.

### 4.3 기존 대출

기존 학자금대출은 최초 입력에서 받지 않는다. 결과에서 `기존 학자금대출이 있나요?`를 선택한 사용자에게만 추가 입력을 제공한다.

- 가능한 경우 일반 상환·취업 후 상환으로 잔액 분리
- 가능한 경우 등록금·생활비 용도 분리
- 약정금리, 남은 거치기간, 남은 상환기간을 알면 실행 일정에 반영
- 세부 약정정보가 없으면 근사 계산 상태와 누락 정보를 표시
- 기존 원금과 신규 원금을 하나의 동일 조건 대출로 합치지 않음

## 5. 추천 엔진

추천은 자격과 계산을 수행하지 않고 두 결과를 입력받아 순서를 결정한다.

```text
eligibility
  -> candidate-builder
  -> repayment-calculator
  -> recommendation-rules
  -> recommendation-score
  -> recommendation-explainer
```

추천 순서는 다음과 같다.

1. 공식 자격과 안전 규칙 적용
2. 확정적으로 불가능한 조합 제거
3. 필수 등록금·희망 생활비 미충족 여부 판정
4. 시나리오 목표 달성 여부 판정
5. 상환 후 희망 생활비 침범 여부 판정
6. 같은 규칙 등급의 후보에만 내부 점수 적용
7. 차이가 작으면 한쪽을 억지로 선정하지 않고 공동 후보 제시

점수는 사용자에게 표시하지 않고 최종 동률 정리에만 사용한다. 점수 구성과 가중치는 `FLOW-02` 구현을 시작하기 전에 추천 설정에 명시하고 순서 테스트를 추가한다. 점수는 앞선 규칙 결과를 뒤집을 수 없다.

추천 결과는 계산문을 새로 만들지 않고 이유 코드를 사용자 문구로 변환한다.

```text
ICL_INTEREST_EXEMPTION
LOW_INITIAL_MANDATORY_PAYMENT
GENERAL_PAYMENT_AFFORDABLE
LOWER_TEN_YEAR_BURDEN
RESIDUAL_BALANCE_WARNING
ELIGIBILITY_CONFIRMATION_REQUIRED
```

세 시나리오 전체를 하나의 객관적 정답으로 순위화하지 않는다. 각 시나리오 안에서 현재 입력에 맞는 대출 구성을 추천하고 사용자가 최소대출안, 균형안 v1, 최대활용안의 교환관계를 직접 선택한다.

## 6. 결과 단계의 조건 확인과 선택

첫 결과는 최초 입력만으로 만든 후보 결과다. 현재 후보의 가능 여부나 비용을 바꿀 때만 다음 정보를 결과에서 요청한다.

- 학부·대학원과 학제
- 출생연도 또는 연령
- 신입·편입·재입학·재학생 여부
- 직전학기 성적과 이수학점
- 장애학생 여부
- 다자녀가구 학생·자립준비청년 여부
- 취업 후 상환 생활비의 긴급생계곤란 예외
- 연령 특례에 필요한 과정·재직 조건
- 취업 후 상환 이자면제 조건
- 기존 학자금대출 정보

조건 확인 후에는 후보 생성, 상환 계산, 추천과 설명을 모두 즉시 다시 계산한다. `지원구간상 후보`와 `최종 대출 승인`을 구분하며 서비스는 승인 결과를 확정하지 않는다.

결과에서 사용자가 변경할 수 있는 값은 다음으로 제한한다.

- 가능한 대출상품 후보
- 생활비 대출 포함 여부
- 일반 상환 졸업 후 준비기간
- 일반 상환 상환기간
- 현재 판정에 필요한 조건
- 기존 학자금대출 정보

원금균등·원리금균등 선택은 제공하지 않는다.

## 7. 결과 정보

각 시나리오는 최소한 다음 정보를 제공한다.

- 등록금 대출 상품과 금액
- 생활비 대출 상품과 금액
- 현재보다 줄어드는 주당 근로시간
- 희망 생활비 미충족액
- 거치 중 월이자
- 상환 시작 시점
- 일반 상환 월 납입액 또는 취업 후 상환 연간 의무상환액
- 10년간 납부이자
- 10년 말 남은 잔액
- 자격 상태와 추가 확인 조건
- 추천 이유와 잔액·변동금리 주의사항
- 계산에 사용한 정책 스냅샷, 기준일과 출처

필요자금, 근로소득, 학기별 대출 실행, 거치이자, 상환액의 계산 순서와 원시값을 `calculationTrace`로 반환한다. 내부 계산은 반올림하지 않고 표시 단계에서만 반올림한다.

## 8. 스트레스 조건

- 취업 6·12개월 지연: 취업 후 소득 시작만 이동하며 일반 상환 약정일은 이동하지 않음
- 초봉 20% 감소: 현재가치 월소득을 80%로 낮춰 120개월 유지
- 졸업 1년 지연: 재학기간·생활비 필요기간·추가 학기 대출 실행을 늘리되 기존 대출 약정은 유지

스트레스 조건을 조합해도 상품 자격, 정책 시행일과 기존 약정이 임의로 바뀌지 않아야 한다.

## 9. 이번 실행의 보류·제외 범위

- 2차원 시나리오 그래프와 그래프 인접 상환액 차이 표시
- 임금상승률, 물가상승률, 미래 상환기준소득과 변동금리 예측
- 원금균등 계산·선택 UI
- 실제 금융정보 자동 불러오기
- 런타임 공식정책 API 의존
- AI가 계산식이나 자격을 생성하는 구조
- 균형안 v1의 경제적 최적화 알고리즘

`GRAPH-01`, `GRAPH-02`와 고정·변동금리 교육 확장은 요구사항을 삭제하지 않고 `보류` 상태로 유지한다.

## 10. 구현 경계와 권장 파일 책임

현재 폴더 구조를 유지하며 다음 책임을 분리한다.

```text
src/policies/loans/       학기별 정책 스냅샷과 출처
src/domain/loans/         자격, 상품·용도 구성, 실행분, 상환 계산
src/domain/scenarios/     최소·균형 v1·최대활용 시나리오 생성
src/domain/recommendations/ 규칙, 점수, 이유 코드
src/application/          프로필·정책·시나리오·추천 조립
src/ui/                   조건 확인, 선택, 결과와 계산 흔적 표시
```

`domain`은 UI 문구와 DOM을 모르며, `ui`는 자격·금액·점수를 다시 계산하지 않는다. 정책값은 `policies` 밖에 숫자로 복제하지 않는다.

- 비대출 등록금 0원·등록금과 동일·등록금 초과 오류

- 연령·학적·성적·학점과 시행일 경계
- 생활비가 이미 충족되는 경우 생활비 대출 0원

- 주 15시간 주휴수당 경계를 지나는 0.5시간 탐색
- 최소대출안·균형안 v1·최대활용안의 근로시간과 대출액 관계
- 최대 근로시간 감소량 0일 때 중복 시나리오 처리
- 학기별 일반 상환 실행분의 거치이자·월 납입액·잔액 합산
- 졸업 후 준비기간 0·1·2년, 10년 상환과 연령·학제 상한
- 졸업·취업 지연에도 기존 일반 상환 약정일 불변
- 취업 후 상환기준소득 미만·동일·초과와 이자면제
- 소득·생활비·기준소득·금리가 120개월 동안 불변
- `ineligible` 제외, `conditional`·`unknown` 조건 확인 후 재계산
- 규칙 결과를 점수가 뒤집지 않음
- 과거 0%·50%·100% 고정 시나리오와 단일 `newLoan` 계산 제거
- 그래프 UI와 그래프 테스트가 이번 실행 범위에 포함되지 않음
