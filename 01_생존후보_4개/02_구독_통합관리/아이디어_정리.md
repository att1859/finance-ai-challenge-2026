# 구독 통합 관리

## 한 문장 정의

> 명세서에서 반복결제를 찾아 실제 서비스와 가입채널을 식별하고, `다음 결제 해지`와 `이미 결제된 금액 환불`을 구분해 올바른 공식 경로와 준비물까지 안내하는 구독 실행 내비게이션.

## 문제와 사용자

주 사용자는 Apple·Google Play·웹·통신사·카드 등 여러 채널에서 구독하는 일반 이용자다. 사용자는 반복결제를 발견한 뒤에도 명세서의 가맹점명이 어떤 서비스인지, 어느 채널로 가입했는지, 해지와 환불을 각각 어디서 해야 하는지 다시 찾아야 한다.

이 문제는 한 번 설명하고 끝나지 않는다. 새로운 구독과 결제채널이 계속 생기고 사업자별 메뉴와 환불정책도 바뀐다.

## 서비스 흐름

1. 사용자가 합성 또는 직접 선택한 카드명세서·영수증을 올린다.
2. 반복 결제 후보와 갱신 가능성을 표시한다.
3. 모호한 가맹점명을 실제 서비스 후보와 연결한다.
4. Apple·Google Play·웹·통신사·카드 중 가입·결제채널을 판별한다.
5. 해지와 환불을 별도 과제로 나누고 공식 규정과 필요한 증빙을 보여준다.
6. 정확한 공식 페이지로 연결하고 접수·완료·재청구 확인 상태를 관리한다.

## 차별점

- `구독을 한곳에 모아 보여준다`는 기능만으로 경쟁하지 않는다.
- 자동 발견에서 빠진 결제를 사용자가 쉽게 보완하게 한다.
- 넓거나 생소한 가맹점명을 실제 서비스 후보로 설명한다.
- 같은 서비스라도 결제채널에 따라 달라지는 해지·환불 주체를 찾아준다.
- 해지와 환불을 분리하고 처리 결과와 다음 청구 중단까지 확인한다.

## AI의 역할

- 명세서의 모호한 가맹점명과 금액·날짜를 바탕으로 서비스 후보를 추정한다.
- 긴 환불정책에서 사용자 상황과 관련된 조건·기한·증빙을 찾아 근거와 함께 설명한다.
- 영수증과 사용자 설명을 환불 요청용 정보로 정리한다.

반복주기와 동일금액 탐지, 공식 링크 라우팅, 상태관리는 규칙으로 처리한다. AI는 환불 가능성을 보장하지 않는다.

## 데이터·권한

- MVP: 합성 카드명세서·이메일 영수증 또는 사용자가 직접 선택해 올린 파일
- 실제 자동화: 금융 마이데이터 사업자와의 제휴 또는 허가된 데이터 연계 필요
- 실행: Apple·Google Play·어카운트인포·각 사업자의 공식 해지·환불 링크

공모전 팀이 공개 API만으로 사용자의 모든 카드·계좌 거래를 가져오는 것은 현실적이지 않다. 금융앱 로그인 스크래핑과 인증정보 저장은 사용하지 않는다.

## 웹 MVP

- 여러 결제채널과 모호한 가맹점명이 섞인 합성 명세서
- 반복결제 후보와 누락 보완 화면
- 가맹점·가입채널 판별 질문
- 해지·환불을 나눈 체크리스트와 공식 딥링크
- 접수·환불대기·완료·다음 달 재청구 확인 상태관리

완전 자동 해지·환불을 약속하지 않고, 사용자가 잘못된 메뉴와 고객센터를 전전하는 단계를 줄이는 데 집중한다.

## 가장 큰 약점

- 왓섭이 자동 발견과 일부 해지 대행까지 제공하고 있어 중복이 크다.
- 정부도 금융보안원 안심 제공 시스템을 활용한 구독 통합관리 기반을 추진하고 있다.
- 금융데이터 연결이 없으면 자동 발견의 완성도가 낮아지고 사용자 업로드에 의존한다.
- 우리 화면에서 범용 해지·환불을 끝내려면 사업자별 권한과 제휴가 필요하다.
- 환불정책 해석 오류는 금전적 기대와 분쟁을 만들 수 있다.

## 추가 확인사항

- 금융보안원 기반 구독관리 서비스의 출시 범위와 참여기관
- 왓섭의 현재 자동발견 커버리지와 직접 해지 가능 가맹점
- 어카운트인포 카드자동납부 해지와 디지털 구독계약 해지의 경계
- Apple·Google 및 주요 국내 서비스의 안정적인 딥링크·제휴 API
- 카드명세서 업로드 분석에 필요한 보안조치와 보유기간
