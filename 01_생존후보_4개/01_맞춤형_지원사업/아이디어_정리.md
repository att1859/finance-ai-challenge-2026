# 맞춤형 지원사업 통합 탐색

## 한 문장 정의

> 사용자의 최소 프로필 하나로 중앙정부·지자체·청년·소상공인 지원 사이트를 함께 검색하고, 중복된 제도와 자격 불확실성을 정리해 정확한 공식 신청처까지 연결하는 `지원 사이트계의 호텔스컴바인`.

## 문제와 사용자

주 사용자는 자신이 받을 수 있는 복지·금융·청년·지역 지원을 찾는 일반 이용자다. 정부24+, 복지로, 온통청년, 지자체 사이트에도 맞춤검색이 있지만 수록 범위와 질문, 최신성, 직접 신청 가능한 범위가 서로 다르다.

문제는 지원정보가 전혀 없는 것이 아니라 사용자가 여러 포털을 옮겨 다니며 같은 조건을 반복 확인하고, 비슷한 이름의 제도와 서로 다른 신청처를 다시 맞춰야 한다는 점이다.

## 서비스 흐름

1. 사용자가 연령·거주지역·가구·취업·사업·관심분야 등 최소 프로필을 입력한다.
2. 서비스가 정부24 공공서비스, 온통청년, 지역·분야별 공식 소스를 함께 검색한다.
3. 같은 제도와 유사한 지원을 묶되 출처와 최종수정일은 보존한다.
4. 결과를 `근거가 충분함 / 추가정보 필요 / 공식 확인 필요`로 나눈다.
5. 부족한 조건은 사용자가 답할 수 있는 추가 질문으로 제시한다.
6. 신청기한·필요서류·인증수단을 준비한 뒤 정확한 공식 신청 화면으로 연결한다.

## 차별점

- 새로운 지원 데이터베이스를 하나 더 만드는 것이 아니라 여러 공식 맞춤서비스의 범위와 실행경로를 비교한다.
- 중앙·지역·청년·소상공인 지원을 한 프로필로 함께 본다.
- 단순히 `받을 수 있다`고 추천하지 않고 판정 근거와 부족한 정보를 보여준다.
- 정보만 제공되는 사이트와 실제 신청 가능한 사이트를 구분하고 정확한 신청처로 보낸다.
- 신청 직전에 필요한 서류와 인증수단을 한곳에서 준비하게 한다.

## AI의 역할

- 비정형 공고에서 대상·조건·기한·서류·신청처를 구조화한다.
- 기관마다 다르게 표현한 비슷한 제도를 찾아 중복 후보를 제시한다.
- 사용자의 자연어 상황을 필요한 추가 질문으로 바꾼다.

연령·지역·기간·소득구간처럼 구조화된 조건 매칭은 규칙으로 처리한다. AI는 수급 가능성을 확정하지 않고, 원문과 해석 결과를 분리해 보여준다.

## 데이터·권한

- 행정안전부 대한민국 공공서비스 정보 API: 전국 공공서비스 목록·상세·지원조건
- 온통청년 API: 청년정책 조건·신청기간·제출서류·신청 URL
- 정부24·복지로·지역 포털의 공개 페이지와 공식 링크

공개 데이터만으로 후보 탐색과 신청 준비는 가능하지만, 주민등록·소득·재산 자동조회와 우리 서비스 안에서의 신청 완료·결과 수신은 인증과 기관 제휴가 필요하다.

## 웹 MVP

- 세 가지 합성 프로필: 서울 청년 구직자, 최근 폐업한 대전 거주자, 수원 출산가구
- 중앙·지역·청년·소상공인 출처를 분리한 통합 결과 화면
- 중복 제도 묶기, 후보가 된 이유, 추가 질문, 신청 마감·서류 표시
- 공식 신청처 딥링크와 신청 전 준비 체크리스트

실제 개인정보를 조회하지 않고 사용자가 선택한 범주와 합성 프로필로 핵심 흐름을 시연한다.

## 가장 큰 약점

- 개인화 혜택 검색 자체는 정부24+ 혜택알리미·복지멤버십·민간 서비스와 중복이 크다.
- 공식 API의 지역 서비스 누락, 중복, 신청 URL 품질과 갱신주기를 실제 샘플로 검증해야 한다.
- 외부 신청 이후 상태를 받을 수 없으면 사용자가 직접 진행상태를 기록해야 한다.
- 통합 범위를 넓힐수록 공고 정합성과 최신성 유지비용이 커진다.

## 추가 확인사항

- 정부24 공공서비스 API의 신청 URL·최종수정일 품질
- 복지로에서 온라인 신청 가능한 서비스의 기계적 구분 가능 여부
- 온통청년 운영 API 승인과 신청 URL 재사용 조건
- 유사한 국내 민간 메타검색의 실제 이용 수준과 빈틈
- 우리 서비스가 외부 신청 결과를 받을 수 있는 공식 연계 규격 존재 여부
