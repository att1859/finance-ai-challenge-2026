# 2차 조사 — 정기결제의 발견·해지·환불

- 조사 기준일: 2026-08-13
- 조사 범위: 국내 사용자 반응, 현재 서비스, 정부 추진안, 금융데이터 권한, 해지·환불 실행 가능성, 해외 벤치마크
- 주의: 커뮤니티 사례는 사용자 자가진술이며, 결제·환불 결과를 독립적으로 검증하지 않았다.

## 1. 먼저 드러난 결론

사용자 불편은 하나가 아니라 다음 일곱 단계로 분해된다.

1. 반복 결제를 발견한다.
2. 명세서의 가맹점명이 실제 어떤 서비스인지 식별한다.
3. Apple·Google Play·웹·통신사·카드 중 어디서 가입했는지 찾는다.
4. 해지와 환불 가능성을 구분한다.
5. 올바른 채널에서 해지한다.
6. 별도로 환불을 신청한다.
7. 처리 결과와 다음 결제 중단을 확인한다.

문제 자체는 실제이고 사례도 반복되지만 경쟁·정책 환경이 빠르게 바뀌고 있다. 국내에는 [왓섭](https://play.google.com/store/apps/details?id=xyz.whatssub.application&hl=ko)이 이미 자동 발견과 일부 해지 대행을 제공하고, 어카운트인포는 계좌·카드 자동납부의 조회·일부 해지·변경을 제공한다. 2026년 6월에는 정부도 금융보안원 안심 제공 시스템을 활용한 구독내역 통합 조회·관리 기반을 지원하겠다고 발표했다.

따라서 “구독을 모아 보여준다”만으로는 중복이 크다. 남은 빈틈은 **가맹점 식별, 결제 채널 판별, 해지와 환불의 분리 안내, 빠진 구독 보완, 환불 가능성의 근거 설명, 처리상태 확인**에 더 가깝다.

### 문제의 성격

- “구독 존재를 모름”과 “알지만 해지 경로를 모름”은 별도 문제다.
- 해지는 다음 결제를 막는 행동이고 환불은 이미 결제된 금액을 돌려달라는 별도 요청이다.
- 결제 서비스명, 명세서 가맹점명, 앱 이름이 일치하지 않을 수 있다.
- 한 번 설명하면 끝나지 않는다. 구독과 결제채널이 계속 추가되고 정책도 변한다.

## 4. 기존 서비스가 잘 안 쓰이거나 완결되지 않는 이유

### 사용자 반응으로 확인된 장벽

[왓섭 Google Play 리뷰](https://play.google.com/store/apps/details?id=xyz.whatssub.application&hl=ko)에서 확인한 사례는 다음과 같다.

- 2026-07-11 리뷰: 가입이 느리고 오픈뱅킹 동의 화면이 데스크톱 형태로 표시되거나 빈 화면이 된다고 설명했다.
- 2023-08-29 리뷰: 여러 결제수단 통합은 유용하지만 일부 수단과 구독, 특히 간편결제 연결이 빠진다고 했다.
- 2021-05-05 리뷰: 인증서를 가져와도 많은 항목이 누락되고 카드·계좌를 수동 등록해야 했다고 했다.

리뷰 시점과 버전이 다르므로 현재도 모두 재현된다고 단정할 수 없다. 다만 자동 발견 서비스의 핵심 위험이 **연결 실패와 누락**이라는 점은 분명하다.

### 구조적 이유

1. 거래 데이터에서 “매달 비슷한 결제”를 찾는 것과 실제 구독계약을 찾는 것은 다르다.
2. Apple·Google·통신사·웹·카드 자동납부는 각기 다른 식별자와 취소 권한을 가진다.
3. 해지 대행에는 사용자의 계정 접근이나 사업자 협력이 필요할 수 있다.
4. 환불은 사업자 정책과 사용 내역, 청약철회·소비자보호 규정에 따라 판단되어 단일 버튼으로 보장하기 어렵다.

## 5. 2026년 정부 추진안이 만드는 변화

[정책브리핑 2026-06-19 발표](https://www.korea.kr/news/policyNewsView.do?newsId=148966805)는 다음을 명시한다.

- 금융보안원의 안심 제공 시스템으로 개인정보를 보호하면서 금융정보를 통합·연계
- 구독내역을 손쉽게 조회하고 관리할 수 있는 기반 지원
- 구독해지를 어렵게 하는 다크패턴 단속·가이드라인·법제화 추진
- 중요한 계약내용 변경의 사전고지·동의절차 개선 추진

공개 발표는 “기반을 지원한다”는 추진안이다. 현재 조사 시점에 전 국민 대상 서비스가 이미 출시되어 모든 구독을 해지·환불한다고 확인된 것은 아니다. 반대로 이 계획을 무시하고 단순 통합조회 MVP를 만들면 제출 시점에 차별점이 더 약해질 가능성이 있다.

## 6. 데이터·인증·API 경계

### 금융거래 자동 발견

[금융위원회 마이데이터 운영 구조](https://www.fsc.go.kr/no010101/75435)는 은행·카드·전자금융 등의 개인신용정보가 표준 API와 본인 전송요구를 통해 마이데이터 사업자에 제공되는 구조를 설명한다. [허가심사 안내](https://www.fsc.go.kr/no010101/77665)는 본인신용정보관리업이 허가제로 운영되며 최소자본금과 보안·소비자보호 심사를 받는다고 밝힌다.

따라서 공모전 팀이 일반 공개 API 키를 발급받아 사용자의 모든 카드·계좌 거래를 가져오는 구조는 현실적이지 않다.

### 가능한 데이터 입력 방식

| 방식 | 구현 가능성 | 장점 | 한계·주의 |
|---|---|---|---|
| 사용자가 구독을 직접 등록 | 즉시 가능 | 금융 라이선스 없이 가능 | 발견 문제를 충분히 해결하지 못함 |
| 카드명세서 CSV/PDF·결제 알림 내역을 사용자가 업로드 | 조건부 가능 | 반복 결제 후보를 분류하는 MVP 가능 | 민감 금융정보 최소수집·마스킹·즉시삭제 필요. PDF 형식 다양성과 오탐 존재 |

| 금융 마이데이터 연결 | 허가·파트너십 필요 | 자동 발견의 핵심 | 팀 단독 MVP에서 공개 API로 구현 불가 |
| 스크래핑으로 사용자 금융앱 로그인 | 사용하지 않는 편이 타당 | 외형상 자동화 | 인증정보 저장, 약관·보안·안정성 위험이 큼 |

| 4 | 외부 화면과 나란히 안내 | 보류 | PiP는 사용자 결정으로 보류. 딥링크 우선 |
| 5 | 공식 임베드·부분 실행 | 대상별로 다름 | 어카운트인포·Apple·Google의 공개 임베드 API는 확인하지 못함. 일부 사업자 제휴가 있어야 함 |
| 6 | 우리 서비스에서 해지·환불 완료 | 범용으로 불가능 | 사업자별 권한·계정·정책 필요. 특정 가맹점 파트너십이 있다면 제한적으로 가능 |

### 우리 화면을 벗어나지 않고 할 수 있는 최대치

- 사용자가 올린 명세서에서 반복 결제 후보 표시
- 가맹점명과 가능한 서비스 후보 대조
- Apple·Google·웹·통신사 중 가입 채널 판별 질문
- “다음 결제 해지”와 “이미 결제된 금액 환불”을 분리
- 환불 가능성을 보장하지 않고 공식 규정·필요증빙·요청기한을 설명
- 정확한 공식 링크와 사용자가 체크하는 진행상태 제공

이 범위는 완전 해지는 아니지만 검색 피로와 잘못된 채널 이동을 줄인다.

## 8. 해외 벤치마크 — Rocket Money

[Rocket Money 구독 관리](https://www.rocketmoney.com/feature/manage-subscriptions)는 연결한 은행계좌·카드 거래에서 반복 결제를 모으고 취소를 지원한다. [공식 도움말](https://help.rocketmoney.com/en/articles/2185531-managing-your-bills-and-subscriptions)은 다음 한계를 명시한다.

- 연결 계좌·카드의 거래를 분석해 자동 발견한다.
- 최근 결제가 없으면 비활성 목록으로 간다.
- 수표나 연결하지 않은 계정의 결제는 사용자가 직접 등록해야 한다.

[취소 도움말](https://help.rocketmoney.com/en/articles/934402-how-do-i-cancel-a-subscription-on-rocket-money)은 취소 대행이 Premium 회원 기능이며, 취소 버튼이 없는 구독은 Rocket Money도 대신 취소할 수 없어 사용자가 직접 하는 안내만 제공한다고 설명한다.

국내에 가져올 핵심은 “해외에서는 다 된다”가 아니다.

- 자동 발견도 연결되지 않은 결제를 놓친다.
- 직접 취소와 방법 안내를 명확히 구분한다.
- 사람이 개입하는 취소 컨시어지는 유료 서비스로 운영된다.
- 국내는 동일한 금융데이터 접근권을 전제로 할 수 없다.

## 9. 남은 제품 기회와 포화 영역

### 비교적 강하게 남은 빈틈

- 모호한 가맹점명을 실제 서비스 후보로 설명
- 결제 채널을 찾아 올바른 해지·환불 주체로 보내기
- 해지와 환불을 한 체크리스트에서 별도 처리
- 누락된 구독을 사용자가 쉽게 보완하고 다음 달에 다시 확인
- 환불 요청에 필요한 날짜·금액·영수증·미사용 여부를 정리
- 처리 결과를 사용자가 기록하고 재청구를 감시

### 이미 서비스가 강한 영역

- 카드·계좌 연결을 통한 반복결제 자동 탐지
- 통합 구독목록과 갱신 알림
- 대표 서비스의 해지방법 안내

### 아직 만들어지지 않았다고 단정할 수 없는 영역

- 모든 국내 가맹점의 해지·환불 상태 통합
- 가맹점별 환불 가능성 예측
- 소비자 분쟁조정까지 이어지는 상태관리

위 기능은 공개 정보가 적어 경쟁 서비스 추가 탐색이 필요하다.

## 10. AI를 억지로 붙이지 않는 설계

- 반복주기 계산, 동일 금액 탐지, 공식 링크 라우팅은 규칙 기반이 설명하기 쉽다.
- AI가 유용할 가능성이 있는 곳은 명세서의 모호한 가맹점명 후보 추정, 긴 환불정책 요약, 사용자 상황과 공식 규정의 근거 연결이다.
- AI가 “환불된다”고 단정하면 안 된다. 가능한 경로, 근거, 불확실성, 최종 판단 주체를 함께 표시해야 한다.

## 12. 현재 판단

이 후보의 사용자 불편은 분명하지만, 자동 발견부터 해지 대행까지 이미 왓섭이 가까이 와 있고 정부의 통합관리 기반도 추진 중이다. 제품 범위를 넓게 “구독관리”라고 잡기보다, **빠진 결제를 보완하고 모호한 가맹점을 식별하며 해지와 환불을 올바른 주체로 연결하는 실행 내비게이션**으로 구체화해야 차이가 생긴다.

완전한 자동 해지·환불을 약속하지 않더라도 사용자가 잘못된 메뉴와 고객센터를 전전하는 단계를 줄이는 가치는 있다. 단, 핵심 발견을 금융계정 자동연결에 의존한다면 라이선스·파트너십이 선행되어야 한다.
