# 학자금 소비평탄화 AI 현행 작업 기준

이 문서는 새 작업 세션이 현재 구현 위치와 최신 제품 결정을 잘못 해석하지 않도록 정리한 실행 기준이다. 기존 단일 페이지 앱의 검증된 계산과 테스트를 유지하면서 제품 문서와 모듈 경계에 맞춰 계속 개발한다.

- 단일 페이지 흐름을 유지하고 앱 내부 모듈 경계를 통해 계산·정책·UI를 분리한다.

- 모든 구현·테스트·빌드 명령은 현행 앱 폴더를 작업 디렉터리로 지정해 실행한다.

## 작업 방식

- 프런트엔드 디자인과 구현에는 `impeccable` 스킬을 사용하고, 가능한 경우 Live 모드로 실제 화면을 보며 반복 수정해.
- 기존 프로젝트 구조를 먼저 파악하고 합리적인 위치에 구현해. 사용자의 기존 변경이나 관련 없는 파일을 덮어쓰지 마.
- 브라우저 조사가 필요하면 Codex 앱 내장 브라우저만 사용해. Chrome 프로필이나 열린 Chrome 탭은 사용하지 마.
- 참고사이트가 별도로 주어지지 않았으므로 현대적인 금융 서비스·재무 시뮬레이터·비교 대시보드 레퍼런스 2~3개를 직접 선정해. 각 사이트에서 참고할 정보 구조나 인터랙션만 짧게 정리하고, 시각물을 그대로 복제하거나 브랜드를 모방하지 마.
- 계획만 제시하고 멈추지 말고 구현, 실행, 브라우저 검수, 수정까지 진행해. 중요한 선택은 아래 권장안으로 처리하고 사소한 확인 질문은 하지 마.

## 제품 정의

서비스명은 임시로 `학자금 소비평탄화 AI`를 사용해. 핵심 약속은 “대출을 많이 받게 하는 서비스”가 아니라 “장학금과 감면을 먼저 찾고, 남은 총필요자금을 근로와 공적 학자금대출로 배치하여 대학 시절의 생활·학업시간과 졸업 후 상환 부담을 함께 평탄화하는 서비스”야.

첫 고객은 국내 학부 재학생이야. 결과의 성공 기준은 대출액 증가가 아니라 확인 가능한 지원사업, 줄일 수 있는 근로시간, 현재와 미래의 총지출 격차, 상환 안전성, 사용자의 계획 이해도야.

## 디자인 방향

- 기존 데모에서는 색상 정체성만 계승해: 짙은 네이비 또는 차콜, 따뜻한 오프화이트, 절제된 라임 포인트.
- 기존 화면 레이아웃과 과도하게 큰 숫자·한 화면 강박은 버려. 페이지는 자연스럽게 세로 스크롤되어도 돼.
- 프리미엄 금융 서비스처럼 차분하고 신뢰감 있게 만들되, 공공기관 사이트처럼 딱딱하거나 평범한 SaaS 대시보드처럼 보이지 않게 해.
- 결과 숫자는 크기만 키우지 말고 비교 관계, 차이, 근거, 위험을 한눈에 이해하게 설계해.
- 데스크톱과 모바일 모두 대응하고, 명확한 포커스 상태·충분한 대비·키보드 접근성을 확보해.
- 장식용 그라디언트, 과도한 글래스모피즘, 의미 없는 AI 반짝이, 모든 요소를 카드로 감싸는 패턴은 피해야 해.

## 핵심 사용자 흐름

1. 서비스 한 문장 설명과 `내 계획 계산하기`
2. 수기 입력 또는 가상 데이터임을 명시한 `예시 정보로 시작하기`
3. 실제 납부 등록금, 확정 지원금, 생활·근로 목표, 졸업까지 남은 기간과 대출 유형 입력
4. 입력 오류와 정보 부족 확인 후 세 가지 계획 계산
5. `학업시간 확보형`, `균형형(기본 보기)`, `부채 최소형` 중 비교할 시나리오 선택
6. 한 그래프에서 대학 생활비 여력·주당 근로시간·상환 후 생활비 여력 비교
7. 선택안의 대출·자금배분·총필요자금 산식 확인
8. 대표 지원사업 후보와 매칭·제외 이유·공식 링크 확인
9. 취업 6개월·12개월 지연, 초봉 20% 감소, 졸업 지연 스트레스 테스트
10. 계산 기준, 정책 기준일과 공식 출처 확인

## 데모 기준값

계산에는 확정된 금액만 사용한다. `학기 등록금`은 확정 장학금·감면 반영 후 학기당 실제 납부액이며, 졸업 전 수혜가 확정된 생활비성 지원금만 별도 입력값으로 차감한다. 지원사업 후보와 금액 미확인 제도는 계산에 자동 반영하지 않는다.

졸업까지 남은 기간은 남은 학기, 생활 개월, 근로소득, 대출 실행과 재학 중 이자에 공통 적용한다. 대출 유형은 취업 후 상환과 일반 상환 중 하나를 필수로 선택하고, 유형에 존재하지 않거나 정책값이 부족한 결과를 0원으로 표시하지 않는다.

- 대학 시절 희망 월 생활소비: 130만원
- 현재 시급: 12,000원
- 현재 주당 근로시간: 20시간
- 주휴수당 제외 월 근로소득: 96만원
- 선택 가능한 주당 근로시간: 0시간, 10시간, 20시간
- 졸업까지 4년은 예시 기본값이며 0.5년 단위로 변경 가능
- 졸업과 동시에 취업하는 기준 시나리오
- 취업 후 월소득: 300만원
- 학자금대출 계산 한도: 5,000만원
- 연이율: 1.5%
- 대출 유형: 취업 후 상환 또는 일반 상환 중 하나 선택
- 일반 상환 기본값: 첫 월급부터 5년간 상환
- 0시간은 학업시간 확보형, 10시간은 균형형, 20시간은 부채 최소형의 출발점으로 사용하고 화면에는 한국어 시나리오명만 표시해.

모든 시나리오에는 다음이 동시에 보여야 해.

- 사용자가 입력한 대학 시절 희망 월 생활소비 130만원
- 시나리오에서 가능한 대학 시절 월 생활소비
- 사용자의 현재·희망 주당 근로시간과 시나리오 근로시간
- 대출 유형에 맞는 졸업 시 예상잔액과 취업 첫해 예상상환액
- 사용자가 입력한 취업 후 희망 월 생활소비
- 시나리오에서 가능한 취업 후 월 생활소비
- 장학금·근로소득·대출이 각각 얼마를 담당하는지
- 취업 지연·초봉 감소·졸업 지연 시 어떻게 바뀌는지

대학 시절 소비가 높은 시나리오는 일반적으로 취업 후 가처분소비가 낮아지고, 근로시간과 대출을 줄이는 시나리오는 대학 시절 소비가 낮거나 학업시간이 줄 수 있다는 교환관계를 왜곡 없이 보여줘. 기존 계산 코드가 있으면 검증 후 재사용하고, 숫자를 화면에만 하드코딩하지 마.

## 지원사업 범위와 상태

MVP는 대표 지원사업 규칙과 공식 링크를 제공하는 범위이며, 실제 보유 범위를 넘어 한국장학재단 전체 사업을 수록했다고 주장하지 마. 자동 판정이 어려운 사업도 숨기지 말고 다음 상태 중 하나로 표시해.

- 자동 매칭 가능
- 추가 심사 필요
- 정보 부족
- 대상 아님
- 모집 종료

각 항목에는 출처 기관, 기준 학기, 최종 확인일, 공식 원문 링크, 매칭 또는 제외 이유를 제공하고 `지원사업 후보 보기`를 눈에 띄게 배치해. 실제 MVP 데이터 범위 밖의 제도를 다 수록한 것처럼 주장하지 말고, 대표 규칙과 데모 범위를 명확히 밝혀.

## 개인정보와 금융정보 표현

- MVP는 비회원·브라우저 세션 계산이 기본이며 실제 고객 금융정보를 서버에 저장하지 않아.
- `샘플 마이데이터`는 명시된 가상 데이터이고 실제 연동이나 로그인처럼 오인시키지 마.
- 주민등록번호, 계좌번호, 인증서, 금융기관 비밀번호를 수집하지 마.
- AI는 공고 구조화와 결과 설명을 담당하고, 규칙엔진이 자격 후보를 계산하며, 계산 엔진이 확정 금액·근로·대출 조합을 계산한다. 이 내부 역할명은 사용자 화면의 핵심 문구로 노출하지 않는다.
- AI가 장학금 수혜나 대출 승인을 확정한다고 말하지 마. 최종 판단은 한국장학재단과 각 기관에 있음을 결과 화면에 명시해.
- 향후 실제 금융연동은 인가된 마이데이터 사업자 또는 금융회사 API 제휴가 필요하다는 경계를 보여줘.

## 구현 품질과 완료 조건

- 기존 기능을 무조건 보존하지 말고 서비스 설계서에 맞지 않는 UI는 교체해. 다만 검증된 계산 로직과 유용한 컴포넌트는 재사용해.
- 로딩, 빈 상태, 입력 오류, 정보 부족, 모집 종료, 계산 불가 상태를 구현해.
- 결과 화면은 세 시나리오를 동일 지표로 비교할 수 있어야 하고, 균형형은 추천이 아니라 초기 `기본 보기`로 표시해.
- 공식 정보와 데모 가정값을 시각적으로 분리하고, 출처·기준일·가정을 사용자가 확인할 수 있게 해.
- 개발 서버를 실행하고 앱 내장 브라우저에서 핵심 흐름을 직접 조작해. 데스크톱과 좁은 화면을 확인하고, 깨짐·잘림·과도한 글자 크기·동작하지 않는 버튼을 수정해.
- 관련 테스트와 빌드를 실행해 실패 원인을 해결해.
- 완료 후 실제 수정 내역을 정확히 5줄로 요약하고, 실행 주소와 주요 파일을 알려줘.

먼저 현재 저장소와 설계서를 읽고 작업 계획을 짧게 세운 다음, 바로 신규 UI 구현을 시작해.
